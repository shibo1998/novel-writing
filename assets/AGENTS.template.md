## 1. 每次开工的固定读取顺序（会话恢复协议）

1. **`.soloent/canon.md`（正典速查表 · 单一来源）** —— 关键值一律从这里取，**不凭印象**
2. `SOLOENT.md`（中央面板：身份、约束、全部文件指针）
3. `.soloent/memory/now.md`（当前进度、数值账目、下一步；含机器可读状态块）
4. `outline/` 里全局架构文档的「会话恢复协议」一节（如有冲突以此为准）
5. **`.soloent/ledger.tsv`（章节账本）** —— 逐章的事实。**它才是「事实」，
   `now.md` 的数值是给人看的摘要。** 第 6 条要复述的状态，来源就是它。
6. 按需读取：`characters/`、`world/`、`outline/`（细纲、伏笔回收总表）、最近 1–3 章正文
7. **开工前先口述复述当前状态与本章任务，再动笔。**

> ⚙️ **上面这套读取顺序已脚本化**：动笔前跑 `python tools/brief.py [章号]`，
> 它会把「上一章末的准确状态 + 本章细纲节拍 + 该接的伏笔 + 在场角色 + 硬性纪律」一次打出来。
> **目的不是省事，是把「凭印象写」换成「照着事实写」**——记忆丢失通常不是忘了，是没去看。

### 1.1 会话与上下文（长篇的隐形杀手）

**文件是事实，会话是缓存。** 缓存可以清、可以压缩、可以换——只要事实在文件里。

- **上下文不是越大越好**：建议上限 **200K–300K**，别用满 1M。
- **到 100–150K 就该考虑开新窗口**；超过 **约 200K** 可能成本激增。
- **一个会话只做一件事**。「每章一停」本身就是天然的隔离边界；
  拆书、卷末大改、设定讨论各自单独开窗口。
- **`/compact` 不能替代落盘**：先落盘，再压缩。
- **开新窗口前必做交接**：`now.md` + `SOLOENT.md §7/§8` + 账本行已更新 → `preflight.py` 通过
  → 会话里还没写进文件的结论已落盘。

> 完整做法见插件的 `docs/11-会话与上下文.md`。
> 恢复不需要靠会话历史：新窗口里读 `SOLOENT.md` + `canon.md` + `now.md`，
> 跑一次 `brief.py`，就回到了现场。

### 1.3 版本控制

**长篇必须有版本控制**——「整章重写禁止」这条纪律要有安全网，不满意才能整体回退。

- **Git 仓库需要手工初始化**（`init_book.py` 不代劳）：`cd <书目录> && git init`。
  初始化/同步已生成托管段 `.gitignore`（排除 `.env`、`.soloent/.api.env` 等密钥与运行时产物），
  首次提交即可安全执行。`doctor.py` 会检查密钥文件是否已被 Git 跟踪。
- **提交时机**：每章过闸后、跑完 `/review` 后、**任何骨架层变更之前**。
- 提交前先过闸：`python tools/preflight.py` → `git add -A && git commit`。
  **这样历史里每个 commit 都是"过闸的版本"**，回退时不会退到有硬伤的中间态。
- 回退优先用 `git checkout <版本> -- <文件>`（单文件）或 `git revert`（可追溯），
  **别用 `git reset --hard` 一把梭**。

> 完整说明见插件的 `docs/13-版本控制.md`。

## 3. 每章固定流程（不得跳步）

> **背景（必读）**：本库发生过两次事故——
> ① **19 章在 69 分钟内连发**，从第 15 章起人物名、性别、人设、年级全线漂移，错误无人核对，
>    自我强化成"第二套设定"；② 第一章重设计时**整章重写**，把四轮迭代过的文本资产整套丢弃。
> 两次都是"纪律写在文档里、执行层失守"。**第 0 步（接地）与第 6 步（闸门）为此而设；
> 第 2／3／4／5 步现由闸门校验留痕强制。**

**0. 接地（强制）**
- 读 `.soloent/canon.md`，**关键值一律从该表取，不凭印象**；
- 跑 `python tools/brief.py [章号]`，把上一章末的真实状态、本章节拍、待接伏笔摆到眼前再动笔。

**1. 起草**
- 按细纲的本章节拍码字。单章默认约 {{default_words}} 字（{{words_range}}，字数服从内容）。
- 分场景推进，严格遵守细纲剧情范围，不得超出。

**2. 句法自查（强制）**
- 按 `ai-anti-patterns.md` 词表逐条过一遍，违规即改。
- 同时对照 `story-style.md` 的「人味」条款——这一章有没有两处"没用"的东西。

**3. 技能三连（强制）**（按说明执行对应 SKILL.md，路径：`{{skills_dir}}\<技能名>\SKILL.md`）
- 标点：`chinese-punctuation`
- 润色：`humanizer-webnovel-cn`
- 节奏：`pacing-control`

**4. 连续性复查（强制）**
- 对照 `world/`、`characters/`、`outline/伏笔回收总表.md`、记忆文件逐项核对，发现冲突**先报告**。

> **2／3／4 三步为什么必须强制**：闸门验的是人名／刻度／字数／账本，
> **验不了 AI 句式结构、人味、钩子质量**——这三步是唯一防线。
> 2026-09-18 的 ch-31、ch-32 两次漏跑，作者当场反馈「AI 味重、不像人写的」。
> 现在闸门会校验第 5 步的留痕行——**缺了就拦**；
> 并且把它与本章机检残留**对撞**——写了留痕但残留还在，同样拦（格式合法 ≠ 真跑过）。

**5. 收尾回写（状态同步 · 缺一步就过不了闸）**
1. 更新 `.soloent/memory/now.md` 状态块与五个小节（当前状态／人物快照／近期情节流／待处理线索／执行评审）；
2. 把下列字段补成该章结束时的状态：{{state_fields}}；
3. 把 `narrative_verified` 也改成同一个章节号 ← **只许手改，`--fix` 不会碰它**；
4. **在 `.soloent/ledger.tsv` 追加一行**（列序：{{ledger_columns}}）。
   这一行是跨章对账的全部依据，**写错一个字，后面几十章都在错的账上走**；
5. 把摘要同步进 **`SOLOENT.md §7`（活跃写作状态）**——中央面板只放摘要，细节在 `now.md`；
6. 每五章额外同步 `relations.md` / `world-rules.md` / `roadmap.md`，以及 `SOLOENT.md §8`；
7. **在 `now.md` 的「流程留痕」小节追加一行**（第 2／3／4／5 步的执行凭证）：
   `[流程] ch-N 自查X 三连Y 复查Z 回写OK`
   X／Y／Z ＝ 该步**发现并修复**的处数（干净章写 0 是正常的，但必须是真跑过的）。
   **闸门会把这一行与本章的机检残留对撞**——留有黑名单词／句式禁项等机检可见的残留
   又没写明理由，等于自查没真跑，直接拦截。确需保留的违规处在行尾加
   `；保留：<理由>`（降为警告，交 /review 复核）。

> ⚠️ **SOLOENT.md §7 过时是最常见的陷阱。** 写了 3 章却没更新状态，
> AI 就会在你实际写到第 8 章时写得像还在第 2 章。

**6. 出章闸门（强制）**
```bash
python tools/preflight.py     # 退出码 0 才许写下一章
```
闸门同时校验**六件事**：单章正典一致性、状态是否已同步、账本是否平（跨章，单章检查看不见的那一层）、
是否批量长跑、**第 2／3／4／5 步是否留痕**（缺留痕即拦截——机器验不了这四步跑没跑，只能验有没有留痕）、
**上一章是否有质量评审记录**（出第 N 章时要求 `notes/review-chapter-<N-1>-*.md` 已存在）。
不通过就停下修，**禁止"先写着后面再改"**。
后台监视器（`tools/start_watcher.ps1`）会在 `chapters/` 一有改动时自动跑对账＋过闸，
**这一层与 AI 是否守流程无关**。

**7. 质量审查（强制，不可跳过）**

> **闸门只管算得出来的东西**——人名、刻度、字数、账本、留痕。
> **AI 句式结构、人味、钩子质量，机检天生看不见。** 这一层只能靠本步。
> 顺序不能反：**先过闸门清硬伤（第 6 步），再做质量评审（第 7 步）。**
> ⚠️ **本步不再是"靠自觉"**：闸门会校验**上一章**的评审产物
> （`notes/review-chapter-<N-1>-<日期>.md`）——出第 N 章时它不在，就直接拦。

1. 按 `ai-anti-patterns.md` 逐条扫（7 类句式 ＋ 词级）；
2. 读 `{{vault}}/skills/wuhang-long-all/5-审查/SKILL.md` 的**模块 3**，
   模拟**毒舌读者／资深编辑**视角做段落级批注——沉浸感、情绪调动、文风红线，
   重点标出「出戏／啰嗦／逻辑不通」**并给改写示范**；
3. 把批注落成 `notes/review-chapter-<章号>-<日期>.md`（闸门认这个文件名）；
4. **发现即改，改完重跑第 6 步的闸门**（改了正文就要重新过闸）。

**8. 停下等确认（强制）**

每章完成后向作者汇报并等待确认或修改意见。**禁止连续生成多章**——
本库历史事故：19 章在 69 分钟内连发，从第 15 章起设定全线漂移。

## 4. 硬性纪律（违反视为不合格）

- **人工门禁**：每章完成后停下，向作者汇报并等待确认或修改意见；**禁止连续生成多章**。
- **过闸纪律**：每章落盘后必须跑 `python tools/preflight.py`，退出码 0 才许写下一章。
- **质量审查纪律**：过闸后**必须**做质量审查（第 7 步）——`ai-anti-patterns.md` 逐条扫
  ＋ `5-审查` 模块 3 的毒舌读者批注。**闸门绿灯 ≠ 质量合格**：它只管算得出来的硬伤，
  AI 句式、人味、钩子质量机检看不见。跳过 = 正文只过了一半的关。
- **四步留痕纪律**：第 2／3／4／5 步（句法自查／技能三连／连续性复查／收尾回写）必须逐条执行，
  并在 `now.md` 追加 `[流程] ch-N 自查X 三连Y 复查Z 回写OK`。**闸门校验这一行，缺失即拦截。**
  闸门只管算得出来的硬伤；**AI 句式、人味、钩子质量全靠这四步**。跳过 = 正文只过了一半的关。
- **留痕对撞纪律**：留痕里的数字必须是**真跑出来的**。闸门把该章的机检残留
  （黑名单词／句式禁项／同段连发／比喻堆砌／章末升华／面板条目）与「自查已完成」的声明对撞——
  留有残留又没写明理由 = 拦截。**格式合法 ≠ 真跑过**；确需保留的违规处在行尾写
  `；保留：<理由>`，无理由的保留一律拦截，写了理由的降为警告并交 /review 复核。
- **单章重设计纪律**：整章重写是禁止的。重设计 = 在旧稿上做外科手术（换触发、加因果、挪落位），
  不是推倒重来。动笔前必须先列**「保留 / 迁移 / 新增 / 删除」四列清单**呈作者确认；
  **已验证文本资产（打磨过的台词、场景节奏、留白动作）只迁移不删除。**
- **预期回顾（每阶段开始前）**：先回看 `1-边界/预期.md`——确认当前方向还符合最初的执念与边界再动笔。
  防的是**越写越偏**。**卡文时第一件事也是看它**：很多"写不下去"其实是偏了，不是没灵感。
- **拍板留档**：骨架层（卷纲/细纲/人设/数值体系）的任何变动，先给选项等作者确认；
  确认后当天在 `notes/` 留档并一次性同步所有受影响档案，**未留档的变动视为未发生**。
- **设定类拍板项一律先列建议与选项，agent 不得单方定案。**
- **单一来源**：改人物或数值口径，先改 `.soloent/canon.md`，再改 `.soloent/book.json` 里对应的机检项，
  最后同步 `SOLOENT.md §6`。**两处不一致 = 机制失效**——不是"工具报错"，
  而是"它以为的和你以为的不是一回事"。
- **摘要留 SOLOENT.md，细节存分档。** 不要把世界观正文粘进中央面板——
  那会让它臃肿到读不动，而它本该是每次开工都读一遍的东西。
- **章末禁令**：禁止说教与升华，必须收在悬念、动作或未尽对话上。
- **标点**：中文全角标点；正文对话一律用标准中文双引号（“ ”），**严禁直角引号「」**。
- **禁读心式直述**（「他心里想」）与「一股XX涌上心头」式套路心理。

**状态同步机制**：`now.md` 顶部有机器可读状态块 `<!-- SOLOENT-STATE ... -->`，
含 `chapter`（可机器同步）与 `narrative_verified`（**只许手改**）。两者必须都等于实际章节号。
**只跑 `--fix` 能修好 `chapter`，但 `narrative_verified` 对不上照样拦**——那道就是防绕过用的。

**章节账本机制**：`consistency_check.py` 只看**单章内部**的写法，`state_sync.py` 只数**章节条数**——
两者都看不见「章与章之间的账」。账本补的就是这一层，并能从当前余额**投影破境日**，
与细纲写死的那天比对——**能在写那一章之前好几章就发现排期对不上**。

> 为什么可信：它管的全是**算得出来**的东西（加减乘除、单调性、上限）。
> 「这一章实际写了什么」算不出来，那一半交给 `brief.py` 与**每章一停**。

## 8. 多书并行（同机同时开几本）

本库是多作品库，同一时间可以有多本书在写。**每本书的会话是独立的**：

- 判定「我现在在哪本书」的唯一依据是**当前工作目录**——工具与钩子都会从 CWD 逐级向上找
  `.soloent/book.json`，找到哪本就算哪本。
- 每本书的 `.soloent/`（canon / ledger / checkpoint / watcher.pid / state_hashes）与
  `notes/对账-*.md` **全部独立**，不会互相覆盖。
- ⚠️ **务必把「具体某本书的目录」作为工作区打开**，不要把作品库根目录当工作区。
  在根目录下工作时没有明确的"当前书"，注入正典只能靠"最近改动的那本"猜测，**可能注入错书**。
- 改完插件的通用层（`{{kit}}/scripts/`、`{{kit}}/assets/AGENTS.template.md`）后，跑一次
  `python "{{kit}}/scripts/sync.py" --all --lib "<作品库根目录>"` 让所有书同步；
  `--check` 只检查不写，可用于定期核对。
