# 正文 (Write)

## Usage
触发指令：`加载正文`、`写正文`、`写一章`、`武行正文`

## 目标
将大纲转化为高质量正文，按章纲分场景撰写，并更新角色状态、伏笔与进度。

## 📌 阶段开始前：回顾预期

**【立即提示用户】**：
> 进入正文阶段前，建议先打开 `1-边界/预期.md`，回顾你的初始执念与边界，确认正文写作方向与预期一致，再开始动笔。

---

## 步骤 0: 一次性初始化 (One-time Setup)

- **目标**：以主角的初始状态作为整个创作阶段的基准。（插件初始化时已创建相关文件，本步仅做更新与链接。）
- **动作**：首次创作前，根据 `XX卷_章纲.md` 的开局设定：
  1. **更新初始状态**：在 `.soloent/memory/now.md` 中记录/更新主角第 0 章（正文开始前）的初始状态。
  2. **链接到 SOLOENT**：确认 `SOLOENT.md §7.2 Character Snapshot` 已写入指针 `-> .soloent/memory/now.md`；若未写入则补上。

---

## 步骤 1：写作前置检查 (Pre-Writing Check)

- **目标**：确保动笔前的所有信息输入是完整且准确的。
- **动作**：在撰写 **每一章** 正文前，必须检查并整合以下关键信息：
  1. **风格约束**：
     - `1-边界/1.2_文风.md`（基础文风 — 路径已注册于 `SOLOENT.md §5`）
     - `1-边界/1.5_微观节奏拆解.md`（如有：导演手册，场景调度/镜头语言）
  2. **红线底线**：项目宪法 `.soloent/constitution/MASTER.md`（路径已注册于 `SOLOENT.md §6`）
  3. **设定支持**：
     - 查阅 `SOLOENT.md §2`（世界观索引）和 `§3`（角色索引），按指针读取对应文件
     - `2-设定/2.3_金手指设定.md`（如有：若本章涉及使用）
  4. **当前状态**：`.soloent/memory/now.md`（路径注册于 `SOLOENT.md §7.2`，确保获取最新状态）
  5. **伏笔与进度**：
     - `outline/伏笔回收总表.md`（路径注册于 `SOLOENT.md §7.4`）
     - `SOLOENT.md §8`（当前阶段与待办）
  6. **本章指令**：`3-大纲/XX卷_章纲.md` 中对应的本章章纲部分。
  7. **上下文参考**：读取 **上一章正文**（确保剧情连贯、语气承接）。
- **目的**：防止逻辑BUG、风格漂移和设定遗忘。

---

## 步骤 2：正文撰写与AI辅助 (Writing with AI)

- **输入**：步骤1中整合的全部信息。
- **动作**：
  - **分场景生成**：严格按照章纲拆解的场景顺序，**逐个场景**进行撰写。
  - **字数锚定**：建议单章总字数在 **2300-4000 字** 之间（用户可根据平台要求自行指定范围）。
  - **文风执行**：严格执行 `1-边界/1.2_文风.md` 的要求，注重"展示而非讲述"(Show, Don't Tell)，强化感官描写。
  - **结尾钩子**：确保章节末尾包含章纲中设计的悬念或钩子。
  - **创作范围**：严格遵守章纲剧情范围，不得超出。
- **输出产物**：`4-正文/第X章_草稿.md`。
- **【强制暂停】** 草稿生成后，**禁止自动进入步骤 3，等待用户明确回复**：
  > 「第 X 章草稿已生成（`4-正文/第X章_草稿.md`），请阅读确认后回复『继续』进行完稿校准。」
- 收到用户『继续』（或等效肯定）后，方可进入步骤 3。

---

## 步骤 3：完稿后校准 (Post-Writing Calibration)

- **动作**：
  1. **严格审查（五项检查）**：
     - **字数检查**：确保单章字数在2300-4000字之间（使用 `scripts/count_chinese_words.py` 统计），可以超出 4000 字，但不能低于 2300 字。
     - **大纲符合性检查**：对照 `XX卷_章纲.md`，检查本章核心事件、场景和结尾钩子是否完全按计划执行。
     - **文风检查**：对照 `1-边界/1.2_文风.md` 和项目宪法，检查是否存在AI写作痕迹。
     - **接续检查**：对照上一章，检查剧情、时间、地点是否无缝接续。
     - **金手指合规性**：（若涉及）检查表现形式是否符合 `2-设定/2.3_金手指设定.md`。
  2. **显式输出【完稿自检卡】**：如果五项检查有一项不通过，必须重新创作，或者进行相应修订。
- **目的**：保持设定与正文的实时同步，确保单章质量达标。

---

## 步骤 4：伏笔、状态与进度更新 (Foreshadowing, State & Progress Update)

⚠️ **CRITICAL STEP**: 此步骤决定了记忆的连续性。绝对不可跳过！

- **状态回写**：根据本章发生的实际剧情，**立即更新**以下文件：
  - `.soloent/memory/now.md` → 角色状态变化（升级/道具/关系）
  - `outline/伏笔回收总表.md` → 新增或收回的伏笔条目
  - `SOLOENT.md §8` → 将本章标记为已完成，填入下章任务
- **执行确认**：必须明确输出"已更新 memory 文件"的反馈，方可结束本章创作循环。

---

## 步骤 4.5：出章一致性闸门（强制）

> 本节灵蟹原版即有，本项目保留并明确其薄壳路径。
> 完整每章循环见 `docs/06-正文.md` 第 6 步。

- **条件**：项目根目录存在 `tools/preflight.py`（说明已启用一致性闸门）。**不存在则跳过本步**。
- **动作**：每写完一章、更新完 memory 后，在项目根目录执行：
  ```
  python tools/consistency_check.py
  python tools/preflight.py
  ```
  - 机检项清单以 `python tools/consistency_check.py --list-checks` 为**唯一来源**（文档不复述）。
  - 关键值以 `.soloent/canon.md`（正典速查表）为准，禁止凭印象。
- **判定**：`preflight.py` 退出码 **0** → 放行；退出码 **1（存在「严重」）** → ❌ **停止**，
  先修到 0，**禁止开始下一章**。
- **批量保护**：若提示「自上次校验后新增 ≥2 章未逐章校验」→ 立即停止批量生成，逐章补过闸
  （判据写死在 `preflight.py`：`latest - last > 1`。早期文档写「≥5 章」，那个 `gate.batch_warn` 配置键从未被任何脚本读取，已作废——2026-09-20 修正。）
  （这正是本库 2026-09 漂移事故的触发条件）。
- **留档**：闸门报告输出到 `notes/对账-YYYY-MM-DD.md`。

---

## 步骤 4.6：质量审查（强制）

> **闸门只管算得出来的东西**——人名、年份、刻度、字数、黑名单词。
> **AI 句式结构、人味、钩子质量，机检天生看不见。** 这一层只能靠本步。
> 完整说明见 `docs/06-正文.md` 第 7 步。

1. **按 `assets/rules/ai-anti-patterns.md` 逐条扫**（7 类句式 + 词级）：
   否定排比／时间切片／「一股·一丝·某种」+抽象情绪／升级式升华／**「他知道」裁判腔**／
   排比三联／情绪定语化／推拉垫字；忽然·突然·猛地（**一页 ≥2 即违规**）／柔化副词／
   生理模板／**比喻每章 ≤2**／眼睛文学／空气时间拟态／复合修饰。
2. **走 `5-审查` 模块 3（正文质检）**：以毒舌读者／资深编辑视角做段落级批注，
   重点标「出戏／啰嗦／逻辑不通」，**并给改写示范**。
3. **改完重跑步骤 4.5**——过闸的正文才是定稿。

**顺序不能反：先过闸门清硬伤，再做质量评审。**

---

## 🚫 循环阻断 (Loop Break)

- **动作**：在完成上述所有步骤（1-4，含 4.5、4.6）后，**必须暂停**。
- **状态检查与分支选择**：
  1. **正常推进**：
     - 检查当前卷 `XX卷_章纲.md`。
     - **有剩余章节**：询问 "第 X 章完成。是否继续第 X+1 章？"
     - **本卷已完**：提示 "本卷完。请加载 **3-大纲** 规划下一卷。"
  2. **剧情偏离/修订**：
     - 若本章剧情与章纲差异较大，或用户表示"有了新想法"。
     - **引导**："检测到/你提到剧情有变化，是否加载 **3-大纲** 的【动态修订】模块，重做后续大纲？"
- **等待**：等待用户明确指令，严禁自动开始下一章。
