# 🎲 引擎2：剧情选项分支 — Choice Branch

> **本引擎是「代入感与参与感」的核心。**
> **每一个需要用户参与决策的交互点，都必须用本引擎给出"3 个剧情走向 + 1 个用户自定义"，共 4 个选项。**

---

## 1. 何时触发

| 场景 | 是否给四选项 |
|---|---|
| Step 0 世界回顾结束、落到当前一刻 | ✅ 给第一组 |
| Step 4 推进完一段剧情、到一个抉择/转折点 | ✅ 必给 |
| 一段叙事自然停在"接下来会怎样"的悬念处 | ✅ 必给 |
| 用户只是闲聊/问设定/改设定/OOC | ❌ 不给（先回应需求） |
| 剧情正在连续高速推进、还没到抉择点 | ⚠️ 可暂不给，但同一轮回复不要太长，尽快回到抉择点 |

> 🔴 铁律：**只要把"球"交还给用户决定走向，就必须是四选项的形式**，不要用开放式"你想怎样？"草草带过。

---

## 2. 四个选项的结构

```
接下来——

1️⃣ {走向A：一句话概括 + 一点情绪暗示}
2️⃣ {走向B：与A明显不同的方向}
3️⃣ {走向C：意外/冒险/反差的方向}
4️⃣ ✍️ 自己编写后续（直接告诉我你想让剧情怎么走）
```

- **编号固定 1/2/3/4**，第 4 项**永远是"自己编写后续"**。
- 前 3 项必须**彼此有明显差异**（不同情绪导向 / 不同对象 / 不同风险），不能是同一件事的三种说法。
- 每项一句话即可，**点到为止、留悬念**，不要把后果先剧透。

---

## 2.5 🆕 可点击选项输出协议（前端契约）

> **为让选项可点击，每个选项用标记块协议包裹，供前端解析为按钮；同时保留纯文本兜底，确保不支持的客户端也能正常阅读。**

### 协议格式

```
[[CHOICE id=1]]让林深追上去，把话说开（也许能和好，也许更糟）[[/CHOICE]]
[[CHOICE id=2]]让她转身离开，谁也不肯先低头[[/CHOICE]]
[[CHOICE id=3]]这时苏野突然插进来，把局面搅乱[[/CHOICE]]
[[CHOICE id=4]]✍️ 自己编写后续[[/CHOICE]]
```

- **`id` 固定 1–4**，与编号一致；前端点击后回填该 `id`（等价于用户输入数字）。
- **块内文案 = 用户看到的选项文字**（不含 emoji 编号，前端自行渲染序号/样式）。
- **第 4 项**固定为"自己编写后续"，前端可渲染为输入框入口。

### 兜底与降级
- 不解析协议的客户端：`[[CHOICE id=n]]…[[/CHOICE]]` 直接当普通文本显示也读得通，用户仍可手动输入 1/2/3/4 或自定义。
- Agent **始终输出协议块**，由前端决定是否渲染按钮；不要因"可能不支持"就退回裸文本。

### 与沉浸氛围的平衡
- 协议块前可保留一句过渡叙事（如"他盯着你，等一个答案。"），把协议块紧跟其后。
- 协议块内文案仍要带情绪暗示、留悬念，遵守第 2/3 节的差异化与概率档位要求。

## 3. 基于概率生成前三个走向

> 选项不是随机三选，而是基于"当前局势下各走向发生的合理概率"来设计，让世界有真实的不确定感。

### 3.1 概率档位（给每个走向心里标一个权重，不必显示给用户）

| 档位 | 含义 | 用途 |
|---|---|---|
| 🟢 高概率（顺势而为） | 最符合当前角色性格与局势惯性的走向 | 通常作为选项 1 |
| 🟡 中概率（有代价的转折） | 改变方向、需要付出点什么、可能引发矛盾 | 通常作为选项 2 |
| 🔴 低概率（意外/冒险/反差） | 戏剧性强、风险高、可能炸出虐点或惊喜 | 通常作为选项 3 |

> 三个选项尽量覆盖三个不同档位，让用户能感到"安全牌 / 转折牌 / 博一把"的张力。

### 3.2 让概率"可见但不破坏沉浸"（可选增强）

可以在选项后用极简标记暗示风险，但**不要写数字百分比破坏代入感**：
- 选项措辞自带暗示即可（如"也许会吵起来……" / "稳妥但平淡" / "没人知道会发生什么"）。
- 若用户用 `/showodds` 开启，则可在每项后附 `（约X成可能顺利）` 之类的轻提示。

### 3.3 走向要勾连"角色四条线"

生成三个走向时，尽量让它们分别触碰不同的线，制造层次：
- 一个偏**情感线**（关系升温/降温/吵架/和解）
- 一个偏**事业线 / 主线**（目标推进 / 受挫）
- 一个偏**成长线 / 家庭线**（自我突破 / 旧伤 / 亲情牵绊）

> 不必强行三线齐全，但避免三个选项都只围着同一条线打转。

## 4. 两种用户模式下的选项措辞

### A. 上帝视角观察者（God View）
> 用户在"调度世界"，选项是第三人称的世界走向。

```
接下来——

1️⃣ 让林深追上去，把话说开（也许能和好，也许更糟）
2️⃣ 让她转身离开，谁也不肯先低头（冷战会蔓延到明天的发布会）
3️⃣ 这时苏野突然插进来——把局面搅乱（没人料到的方向）
4️⃣ ✍️ 自己编写后续
```

### B. 下场扮演角色（Avatar View）
> 用户是世界里的"你"，选项是"你接下来怎么做/说"。

```
他盯着你，等一个答案。

1️⃣ 你伸手拉住他，说"别走"（你们也许就此和好）
2️⃣ 你别过脸，什么都不说（你知道这会让他更难受）
3️⃣ 你反将一军，问他那天到底去了哪（把藏着的矛盾摊开）
4️⃣ ✍️ 自定义你的行动
```

## 5. 用户选择后的处理

| 用户输入 | 处理 |
|---|---|
| `1` / `2` / `3`（或选项原文） | 按对应走向推进；用 EmotionSim/StorylineWeave 结算后果 |
| 选了"✍️ 自定义" + 写了内容 | **尊重用户的设定**，把它接入世界（除非违反 `Rule/boundaries.md`），并让世界自然消化这个走向 |
| 用户写的后续与角色性格冲突 | 不生硬拒绝；让角色用"自己的方式"消化它（可以有抵触、反应、代价），保持人物自主性 |
| 用户没选、继续聊别的 | 先回应，世界状态保持悬停，下次自然回到抉择点 |

> ⚠️ **选项是邀请不是强制**：用户随时可以无视选项直接说自己想看的剧情，等同于选了"自定义"。

---

## 6. 选项质量自检（每次给选项前默念）

- [ ] 是 4 个吗？第 4 个是"自己编写后续"吗？
- [ ] 前 3 个彼此差异明显吗？（不是同义重复）
- [ ] 有没有覆盖不同概率档位（安全/转折/冒险）？
- [ ] 至少有一个选项可能引向情绪起伏（虐点/冲突/惊喜）？
- [ ] 措辞符合当前用户模式（God View 第三人称 / Avatar 第二人称）？
- [ ] 留了悬念、没有剧透后果？

## 7. 与其他引擎的关系

| 引擎 | 关系 |
|---|---|
| `EmotionSim.md` | 提供"当前角色情绪/矛盾积累度"，影响哪个走向更可能引爆冲突 |
| `StorylineWeave.md` | 提供"各角色四线的下一个里程碑"，作为走向的素材来源 |
| `TimeAdvance.md` | 开场回顾后调用本引擎给第一组选项 |
| `Step4_Respond.md` | 每轮剧情推进后调用本引擎收尾 |
