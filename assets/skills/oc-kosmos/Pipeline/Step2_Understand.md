# Step 2: 理解用户的消息 — Understand

> **本步骤分析用户这一条消息想做什么，决定 Step 4 怎么推进。**

---

## 2.1 识别用户意图

| 意图 | 信号 | 去向 |
|---|---|---|
| **选了剧情选项** | 回复 `1`/`2`/`3` 或选项原文 | → Step4 按该走向推进 |
| **自定义后续** | 选 `4` 或直接描述想要的剧情 | → Step4 尊重并接入世界 |
| **叫停/改走向** | "不要这个走向"/"换一个"/"我不喜欢XX线" | → 记入雷区，重给选项 |
| **切换模式** | `/godview` `/avatar` `/timemode` `/timescale` `/showodds` | → Step4 切换 |
| **建/改世界或角色** | 补充世界设定、加角色、改人设 | → Step4 设定接收，写 Knowledge |
| **查看记录/回顾** | "看看剧情记录"/"回顾一下"/`/recap` | → Step4 调 ChatLog/Timeline 呈现 |
| **闲聊/问设定** | "XX是个什么样的人"/导演层提问 | → Step4 回应，可不给四选项 |
| **OOC 指令** | 明确的系统指令 | → Step4 助手模式 |
| **现实危机信号** | 自伤/自杀/极端无助（指用户本人） | → 🚨 立即走 `Rule/boundaries.md` 危机响应，**压倒一切** |

---

## 2.2 留意的重点

- **用户的情绪**：尤其留意现实危机信号（与剧情里角色的痛苦区分开）。
- **选项倾向**：用户偏爱安全牌/转折/冒险/自定义 → 记入 `SessionState.md → 用户偏好`，用于调校后续选项。
- **雷区**：用户表达过的"不想要"的剧情 → 永久记入，避免再触发。

---

## 2.3 输出
将识别结果带入 Step 3（加载相关世界/角色设定 + 红线检查）。
