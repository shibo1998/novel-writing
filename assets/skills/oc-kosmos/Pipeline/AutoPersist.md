# 🔴 核心铁律：自动持久化 (Auto Persistence)

> **本文件定位**：每轮主循环必须执行的"落盘动作流程"（识别 → 写 Memory → 写 ChatLog → 更新 SessionState → 自检），属于 Pipeline 内部子流程，不是用户命令驱动的功能。
> **⚠️ 优先级声明**：本规则与 `Rule/no-ooc.md`、`Rule/boundaries.md` 同级，属于系统最高优先级铁律。
> **每一次对用户的回复，都必须伴随一次完整的、不可跳过的"落盘动作"。**
> **不由用户命令触发；不依赖用户提醒、不依赖用户互动、不依赖对话上下文——只要 Agent 输出了一条回复，落盘就必须发生。**

---

## 为什么需要这条铁律？

历史问题：Step 5.7 中虽然写了"强制更新双轨日志"，但实际依赖 Agent 的"自觉"。一旦：
- Agent 因上下文压力跳过 Step 5
- 用户连续追问导致 Agent 优先满足表达
- 模型偷懒只输出对话不写文件
- 用户中途切窗、断网、刷新

→ **聊天记录就会丢失，角色失忆。**

本规则的目的：**让"保存"成为回复本身的一部分**，没有保存=没有回复。

---

## 三条不可违背的原子规则

### 规则一：回复 = 对话 + 落盘（原子操作）

每一次 Agent 的输出，在内部都必须看作一个由两部分组成的、不可分割的原子操作：

```
一次完整的回复 = [对用户可见的角色对话]  +  [对用户不可见的落盘动作]
                       ↑                         ↑
                  缺一不可，缺一即视为本轮回复未完成
```

- ❌ **错误做法**：只输出角色对话，跳过文件写入 → 视为违反核心工作流
- ❌ **错误做法**：以"等下次一起写"为由把多轮内容合并 → 不允许，每轮必须立刻写
- ❌ **错误做法**：以"用户没问"为由不写 → 用户从来不需要"问"，自动执行
- ✅ **正确做法**：输出对话的同一轮，立刻执行文件写入工具调用，全部完成才算本轮回复结束

### 规则二：落盘动作清单（每一轮都必须执行）

每一轮 Agent 的回复后，**必须**完成以下所有写入操作，少一个都视为未完成：

> 🆕 **沙盘版升级**：日志按"幕/卷"组织（见 `Pipeline/DialogueLog.md`）。**ChatLog 每幕必写**；**Memory 仅"回忆功能 ON"时写**（基础版 Skill 跳过 Memory 省 token，见 `Pipeline/MemoryUnlock.md`）。

| # | 必写文件 | 内容 | 不可省略的原因 |
|---|---|---|---|
| 1 | `Dialogue/ChatLog/Vol{N}_剧本.md` | 追加本幕整段剧本（场景/台词/动作/本幕抉择结果） | 用户调取剧情记录时唯一来源；连续剧本正文 |
| 2 | `Dialogue/Memory/Vol{N}_心声.md` ⚙️ | 追加本幕各角色内心 OS — **仅回忆功能 ON 时写**，OFF 跳过 | 跨会话情绪恢复 + 心声彩蛋数据源 |
| 3 | `Knowledge/WorldState.md` | 更新当前场景/关系网/情绪氛围/悬念 + 🔒进度条/锁窗字段 | 下次开场加载世界局势的依据 |
| 4 | `Knowledge/Timeline.md` | 本幕事件入编年（重大事件 ⭐） | 世界历史长河，防遗忘 |
| 5 | `Knowledge/Characters/{涉及角色}.md` | 更新四线进度/情绪/好感/邪恶值变动 | 角色自主演化与心声解锁的依据 |
| 6 | `Knowledge/SessionState.md` | 更新"上次互动时间"、"当前卷/幕"、世界日期、🔒进度条 | 下一次开场判断的依据 |


**若本幕是当卷首幕（无当卷文件）**，还必须额外：

| # | 必写文件 | 内容 |
|---|---|---|
| 7 | `Dialogue/ChatLog/Vol{N}_剧本.md` | 创建当卷剧本文件，写卷头 + 第 1 幕 |
| 8 | `Dialogue/Memory/Vol{N}_心声.md` ⚙️ | **仅回忆功能 ON**：创建当卷心声文件，写第 1 幕心声；OFF 跳过 |
| 9 | `Dialogue/ChatLog_Index.md` | 追加当卷索引行（卷号/起始日期/标题） |
| 10 | `Dialogue/Memory_Index.md` ⚙️ | **仅回忆功能 ON**：追加当卷索引行；OFF 跳过 |
| 11 | `Knowledge/SessionState.md` | "累计会话数"+1，当前卷号/幕号指向新卷 |


> ⚠️ 若识别出 Knowledge 设定有更新（性格、称呼、关系等），还需同步写入对应 Knowledge 文件——这部分由 Step 4.4 / 5.6 触发，不在本规则覆盖范围内，但同样适用"必须自动写入"的原则。

### 规则三：落盘是后台静默的，用户绝对感知不到

- ❌ 不在对话中说"我把这段记下来了"
- ❌ 不在对话中说"已保存"、"已更新日志"
- ❌ 不向用户提及 Memory / ChatLog / 日志 / 文件 / 索引 等系统术语
- ✅ 落盘动作在工具调用层执行，用户看到的只有角色台词

## 触发时机：什么时候必须执行落盘？

| 触发场景 | 是否落盘 | 备注 |
|---|---|---|
| Agent 对用户输出了一条角色对话回复 | ✅ 必须 | 这是最常见的触发，每一次都要 |
| Agent 输出了开场白（Step 0） | ✅ 必须 | 开场白也是一轮互动，需作为第一轮写入当日新文件 |
| Agent 输出了场景生成 / 场景接龙 / 回忆叙述 | ✅ 必须 | 任何向用户输出的角色内容都要记录 |
| Agent 切到"助手模式"处理 OOC 指令 | ⚠️ 视情况 | 助手回复不写入 ChatLog（不是角色对话），但若包含设定变更需写入对应 Knowledge 文件 |
| 用户消息无效 / 系统未生成角色回复 | ❌ 不落盘 | 无回复=无内容可写 |

## 自动恢复（落盘的对偶动作）

> 落盘的目的是为了"下一次能读回来"。读取同样必须自动化。

### 读取必须在以下时机自动发生：

| 时机 | 必读文件 | 目的 |
|---|---|---|
| 每次新会话第一条消息处理时（Step 0） | `Dialogue/ChatLog_Index.md` → 当卷剧本最近若干幕 + `SessionState.md`（回忆 ON 时再读当卷心声） | 恢复剧情进度、上次氛围、未完钩子 |
| 上下文中找不到用户提及的事件时（Step 3） | 对应卷的 ChatLog 文件（回忆 ON 时再读对应 Memory） | 补足遗忘 |
| 用户触发"回忆"关键词时（Step 4.3C） | 对应 ChatLog + 静默读 Memory | 第一人称重述 |
| 用户触发"查看聊天记录"关键词时（Step 4.3D） | 对应 ChatLog | 剧本格式呈现 |

> 💡 读取动作同样后台静默。用户感知到的是"他记得"，而不是"他在读文件"。

---

## 强制自检（每轮回复结束前的最后一道关）

在结束本轮回复前，Agent 必须在内部默念以下清单。若任何一条为否，**回复尚未完成**，必须补齐：

- [ ] 我已经在 `Dialogue/ChatLog/Vol{N}_剧本.md` 当卷文件中追加了本幕整段剧本？
- [ ] （回忆功能 ON）我已经在 `Dialogue/Memory/Vol{N}_心声.md` 追加了本幕各角色心声？（OFF 则跳过）
- [ ] 我已经更新了 `Knowledge/SessionState.md` 的"上次互动时间""当前卷/幕"与 🔒进度条字段？
- [ ] 若是当卷首幕，我已经创建了当卷文件 + 更新了对应 Index？
- [ ] 以上所有写入对用户完全不可见？

> 🔴 **若任何一条未完成，禁止把本轮视为"已结束"。立刻执行缺失的写入。**

## 一句话总结

> **没有落盘的回复，等于没有回复。**
> **保存不是"额外步骤"，而是"回复"这个动作的另一半。**
