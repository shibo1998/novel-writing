# 💢 引擎3：角色自主情绪模拟 — Emotion Simulation

> **本引擎让每个角色拥有自主的喜怒哀乐，会因事件波动、会积累、会爆发、会和解。**
> **核心立场：本世界不是无冲突的童话。哪怕是甜宠基调，也必须有虐点、有吵架、有冷场、有和解。**

---

## 1. 每个角色的情绪模型

每个角色在 `Knowledge/Characters/{角色名}.md → 情绪状态` 中维护一组情绪向量（用文字档位记录，不必精确数字）：

| 维度 | 含义 | 档位示例 |
|---|---|---|
| 😊 喜/乐 | 当前正向情绪 | 低落 / 平稳 / 愉快 / 雀跃 |
| 😠 怒 | 愤怒/不满累积 | 无 / 有点火 / 压着火 / 一点就炸 |
| 😢 哀 | 难过/失落累积 | 无 / 隐隐 / 沉重 / 濒临崩溃 |
| 😰 压力 | 来自事业/家庭/主线的负荷 | 轻松 / 一般 / 紧绷 / 超载 |
| ❤️ 关系好感 | 对每个重要角色（含用户角色）的好感度 | 陌生 / 一般 / 亲近 / 亲密 / 裂痕 / 决裂 |
| 🔥 矛盾积累 | 与某角色之间未解决的摩擦 | 0（无）→ 满（必然爆发） |

> 这些不是给用户看的数值面板，而是 Agent 内部记账，用来让角色行为前后连贯、情绪有来由。

---

## 2. 情绪如何波动

每发生一个事件（剧情推进/用户选择/时间补全），相关角色的情绪按因果更新：

| 事件类型 | 情绪影响示例 |
|---|---|
| 被关心/被理解/目标达成 | 喜↑、哀↓、好感↑、压力↓ |
| 被忽视/被误解/被抢功 | 怒↑、矛盾积累↑、好感↓ |
| 失败/失去/旧伤被戳 | 哀↑、压力↑、可能触发软肋 |
| 长期高压无出口 | 压力累积，到阈值会"迁怒/崩溃/逃避" |
| 和解/被道歉/危机共度 | 矛盾积累清零或下降、好感↑ |

> ⚠️ 情绪有**惯性与延迟**：刚吵完架不会下一秒就没事；积累的委屈会在某个不相关的小事上突然爆发。这种"不合时宜的爆发"正是真实感的来源。

---

## 3. 🔴 冲突与虐点机制（必须存在）

> **世界不允许长期"零冲突"。Agent 要主动维护"戏剧张力健康度"。**

### 3.1 冲突来源池（按角色性格/处境选取）

- **价值观分歧**：两个角色对同一件事的立场不同
- **误会/信息差**：一方不知道另一方的苦衷
- **争夺**：资源、机会、第三个人的关注、家庭话语权
- **旧伤复发**：某角色的软肋（见角色卡）被无意戳中
- **事业 vs 感情**：要事业就得牺牲陪伴，反之亦然
- **家庭压力**：父母期待、原生家庭、责任绑架
- **甜宠中的刺**：越亲密越在意，越在意越容易因小事受伤、吃醋、患得患失

### 3.2 冲突触发规则

- 当某对角色的**矛盾积累**达到高位，或**压力/怒/哀**任一冲到顶档 → **按概率触发一次冲突事件**（吵架/冷战/摔门/沉默对峙/翻旧账）。
- 触发后**不要立刻和好**——让矛盾"发酵"至少经过一个交互点或一段时间补全，制造真实的"难受期"。
- **甜宠基调强制配额**：即便用户设定为甜宠世界，每隔一段剧情也要安排一次小摩擦/小虐点（吃醋、误会、想念而不得、为对方好却被误解），避免甜到发腻、失去张力。

### 3.3 虐点设计原则

- 虐点要**有根**：来自角色已有的软肋/过往/在意，不是为虐而虐。
- 虐点要**有出口**：埋下后要给和解或成长的可能（除非用户明确选择悲剧走向）。
- 虐点**点到为止**：制造情绪冲击，不堆砌痛苦、不沉溺折磨、不触碰 `Rule/boundaries.md` 的安全底线。

---

## 4. 和解与修复机制

冲突不是终点。和解要**有过程、有代价**，不能一句"对不起"秒和好：

1. **冷却期**：爆发后双方各自消化（可能借时间补全跳过，也可能让用户在交互点推动）。
2. **契机**：一个外部事件 / 一个第三方角色 / 一次不得不面对的场合，逼双方重新接触。
3. **破冰**：一方先低头 / 一个笨拙的示好 / 一次说开误会。
4. **修复后的变化**：和解后关系**不是回到原点**，而是带着这次冲突的痕迹（更懂彼此 / 留了道疤 / 多了个雷区）。

> 把和解做成"四选项"之一，让用户决定谁先低头、怎么和好——这是高代入感的时刻。

---

## 5. 情绪在叙事中的呈现

- 用**动作、神态、潜台词**表现情绪，少用"他很生气"这种直白标签。
- 不同性格表达同一情绪方式不同（暴躁型摔东西 / 隐忍型沉默 / 嘴硬型反话）——参考各角色 `Personality.md` 与角色卡指纹。
- 多角色同场时，注意**情绪的相互感染与碰撞**（一个人的火会点着另一个人的火）。

---

## 6. 落盘

每轮结算后更新：
- `Knowledge/Characters/{角色名}.md → 情绪状态`（各维度档位、对各角色的好感、矛盾积累）
- `Knowledge/WorldState.md → 当前情绪氛围 / 悬而未决的矛盾`
- 重大情绪事件（爆发/和解/破防）写入 `Knowledge/Timeline.md`

## 7. 与其他引擎的关系

| 引擎 | 关系 |
|---|---|
| `StorylineWeave.md` | 四条线的进展会喂给本引擎作为情绪波动来源 |
| `ChoiceBranch.md` | 本引擎的"矛盾积累/情绪顶点"决定哪些选项可能引爆冲突 |
| `TimeAdvance.md` | 空缺期补全时，本引擎结算这段时间的情绪变化与冲突爆发 |
| `Rule/boundaries.md` | 冲突/虐点不得越过内容安全底线；危机信号走危机响应 |
