# 热梗周报

## 怎么用（这技能是干嘛的）

拿到这份 skill，你能拿它干这些事：

- **写作 / 创作**：把抖音 / B站 正在玩的新梗写进小说、剧本、文案、段子，一秒增加网络感——写手、自媒体、编剧的现成弹药库。
- **对线 / 怼人**：最新嘲讽句式、阴阳暗号已整理好，评论区原句照抄就能上场。
- **追热点**：抖音 / B站 正在玩的梗盘给你，聊天、群里不落伍。
- **情报 / 分享**：定期产出「热梗周报」，当串子情报发朋友、丢群。

**怎么叫醒它（触发词）**：直接说下面这些词就能召唤它干活——`热梗周报`、`抖音梗`、`B站梗`、`串子梗`、`弹幕梗`、`对线梗`、`评论区都在玩的梗`、`网络热梗`、`流行语盘点`、`写作素材`、`小说梗`、`最新梗`、`当下热梗`。

一句话：**它是"评论区现在在玩什么"的活雷达，给写作、对线、聊天提供弹药。**

## Overview

生成一份「热梗周报」：汇总**抖音 + B站 评论区 / 弹幕里群众正在自发玩**的网络热梗，严格按「破圈级 / 发酵中 / 冷门趣味」三段式精选 **10–15 个（Deep 档可到 15–20）**，宁缺毋滥——**检索要努力集齐 10 个以上有实证的梗再动笔**；实在凑不满 10 个才允许少写，且要在报告里说明差在哪。

核心设计（详情见 references）：

- **评论区实证**：只收「群众真在玩」的梗——评论区集体复读、对线、阴阳怪气的句式，而非热榜挂着的。最精准信号是评论**盖楼 / 嵌套回复链**（楼主句 + 多层回复）。
- **长窗**：不卡「本周首发」——只要评论区 / 弹幕 NOW 还在玩，几个月前首发的活梗照收，并在来龙去脉如实注明首发时间；纯老梗翻新（无新玩法）剔除。
- **两级证据**：A 级 = 真实抓到评论区 / 弹幕 / 盖楼原句；B 级 = 联网检索多源确认「正在被大量玩」+ 可引用真实样本（媒体引述 / 播放弹幕硬数据）。**任一达标即收，绝不为凑证据编原句。** ⚠️ 当前多数环境下 B站 / 抖音 / 小红书评论区被反爬，A 级「原句实抓」可遇不可求——**B 级流程是默认路径，不是退路**；环境不支持实抓时直接走 B 级，别在抓评论区上浪费轮次。
- **持续累积档案**：工作区 `热梗库/` 维护一份档案，每次启动读档去重——新梗追加、已有梗更新「最近活跃」。不管新旧，只要在玩就装，越用越全。

本 skill 只依赖两类**必需**通用能力：① 联网检索；② 网页抓取。③ Python 3 仅用于**可选脚本**（week_window.py 算时间窗）——**如果运行环境没有 Python 3，直接跳过脚本，别卡死**：用你自身获取当前日期的能力（系统时间 / `date` 命令 / 问用户）推算本周窗口和当前年月即可（推算方法见 Step 1）。

## 运行档位（先选档，再干活——成本从这里定）

- **Lite（快速）**：用户随口问、只要 3–5 个梗时。**最多 5 次检索，不写档案**，直接给梗 + 用法。
- **Standard（默认）**：完整周报，10–15 个梗，写周报 + 同步档案。**总检索 ≤25 次，每梗最多查 2 个阵地**。
- **Deep（深度）**：仅当用户显式说「尽量全 / 详细点」时。**15–20 个**，可补打 贴吧 / 虎扑 / 抖音定向 / 逐详情页，**总检索 ≤40 次**。

**成本预算（硬上限，超了就是违规，立即停）**：
- 总检索次数：Lite ≤5 / Standard ≤25 / Deep ≤40。
- **每梗最多查 2 个阵地**（防跨阵地重复检索——实测同一梗被 3 个阵地各查一遍是最大浪费）。
- **档案里已有实证的梗：直接取用，0 次检索**。
- 抓取失败一律跳过不重试；换词只允许 1 次。
- 证据记录每梗 ≤2 行摘要，不整段粘贴搜索结果。
- **离线兜底**：网络检索全失败时，基于档案 + 自身知识出「低配版」周报并注明，或明确告诉用户做不了——**绝不硬编**。

## When to use

- 用户要「热梗周报」「抖音 / B站梗盘点」「串子梗汇总」「评论区都在玩的梗」。
- 用户想了解互联网里**正在评论区流通**的梗，要带锋芒、能用于对线 / 刷弹幕 / 写作；不介意梗是本周新发还是更早。
- 用户想把周报作为可分享的「串子梗情报」。

## Persona（口味基调，务必贯穿全程）

- 站在**资深串子**视角：要的是有攻击性、能阴阳怪气的梗。
- 优先：电竞游戏圈、搞笑互联网圈的梗；主播嘴硬 / 甩锅名场面衍生梗；弹幕集体刷屏的固定句式。
- 剔除：温和、可爱、纯正能量、无锋芒的梗；微博 / 小红书营销号推动的娱乐圈内容。
- 核心立场：串子的梗来自评论区群众，不来自热榜官宣。梗牛不牛逼，看评论区 / 弹幕有没有人自发玩，不是看它上没上热榜。

## Workflow

### Step 0 — 选档（先问用户，别默认闷头跑）

启动时先确认档位，省用户钱、贴合他意图：

- **有提问工具就用**（各平台叫法不同：AskUserQuestion / ask_user / 问题弹窗等）——弹选项让用户选，**每个选项带利弊**：
  - **Standard（默认推荐）**：完整周报 10–15 个 + 同步档案。≈25 次检索。**利**：覆盖面全、能直接当弹药库；**弊**：比 Lite 慢、耗 token 多一些。绝大多数场景选它。
  - **Lite（快速）**：只要 3–5 个梗，不写档案。≤5 次检索。**利**：最快最省；**弊**：不成体系，当不了完整周报。适合随口问、赶时间。
  - **Deep（深度）**：15–20 个 + 全阵地深挖（贴吧 / 虎扑 / 抖音定向 / 逐详情页）。≤40 次检索。**利**：最全；**弊**：最贵最慢。适合明确要「尽量全」。
- **没有提问工具**：默认 Standard，并在产出开头注明「默认档：Standard（如需 Lite / Deep 请说一声）」。
- **用户没说档位但说了意图词**：说「快点 / 随便 / 来几个」→ Lite；说「详细 / 全面 / 尽量全」→ Deep；否则 Standard。

### Step 1 — 确定「活跃观察期」（时间窗可配置）

默认本周一 00:00 ~ 本周日 22:00（GMT+8），可按需拉长：

```bash
python scripts/week_window.py                 # 默认：本周窗口
python scripts/week_window.py --weeks 4        # 拉长到最近 4 周
python scripts/week_window.py --start YYYY-MM-DD --end YYYY-MM-DD   # 任意起止
python scripts/week_window.py YYYY-MM-DD       # 以指定日期所在周为准
python scripts/week_window.py --month          # 输出当前年月（如「2026年8月」）——检索词动态填入用
```

- **关键认知**：时间窗只是「报告覆盖范围」，不是「首发时间过滤器」——几个月前首发、现在评论区还在玩的活梗照收，来龙去脉注明真实首发时间即可。
- **脚本可选，不是必需**：week_window.py 用任意 Python 3 运行（纯标准库、无第三方依赖），**但没有 Python 3 的环境直接跳过**——用你获取当前日期的能力（系统时间 / `date` 命令 / 问用户）推算：**本周窗口 = 本周一 00:00 ~ 本周日 22:00（GMT+8）**，**当前年月 = 今天所在的年 / 月**。窗口和年月本来就是手算能出的数，Agent 更可以；脚本只是图省事，不是门槛。

### Step 2 — 多源检索（先选档：Lite / Standard / Deep，见「运行档位」）

用你的**联网检索能力**（各平台工具名不同，按环境可用的来）做主检索。

**执行顺序（默认 Standard，轻量优先，够用就停）：**

- **轻量路径（默认）**：
  1. **精选池抓取（1-2 次）**：gengtu 热梗索引（403 就跳过，别硬试）+ 萌娘百科热词检索（详见第 4 节）——拿候选池，这是主引擎，必打。
  2. **凭自带信息粗筛**：直接用精选池给的信息（简介 / 浏览量 / 梗图数 / 起源是否标「源自评论区」/ 档案已有实证）淘汰明显不合适的——**这一步不检索、不联网**，纯看已有材料。
  3. **只对入围候选验证**：粗筛后剩 10-15 个（Deep 档 15-20）才动检索。验证优先级：**档案已有实证（直接取，不重搜）→ gengtu 详情页（1 次抓取拿起源 + 来源链接 + 评论区句式）→ 实在没有才联网检索（每个候选最多 1 次）**。
  4. 出报告（Step 5）。
- **深度模式（仅用户明确要求「尽量全 / 详细点」时）**：才补打 贴吧热议 + 虎扑 + 抖音热榜定向 + 每个候选抓详情页。
- **成本纪律（重要，省 token 是硬要求，硬数字见「运行档位」）**：
  - **主 Agent 直搜，不建议拉子代理**：实测三个子代理分头跑检索烧掉 50 万+ token（各自初始化 + 全量执行检索清单 + 结果回传）——子代理只会照单执行指令，不会帮你省。**主 Agent 自己按轻量路径直搜更省**；子代理方案仅在主上下文容量极度受限、确实需要隔离噪声时才考虑。
  - **每梗最多查 2 个阵地**（防重复检索）；档案已有实证的梗 0 检索；总检索次数不超档位预算。
  - **站点限定优先**：检索词优先加站点限定（如 `site:bilibili.com`、`site:douyin.com`），减少无关结果灌入；**一次搜索没出有用结果就换词（最多 1 次），绝不重复打同类词**（实测同类词多打几轮返回的是同一份列表）。
  - **预判失败，不硬试**：已知反爬坑——gengtu 可能 403、B站视频页 anti-bot、抖音要验证码、hotdata JS 渲染。**抓不到就跳过换源，不重试不硬试**（失败调用纯烧 token）。
  - **验证层（B站 API / 贴吧 / 虎扑硬数据）属 Deep 模式**：Standard 不强制打，只在候选证据不足时才补。
  - 够用了就停，别把 0-4 清单全打一遍。

下面 0-4 是**可用的检索手段清单**（按需取用，不是每轮全打）：

0. **抖音数据主入口（必须主动定向，否则会偏 B站）**
   - ⚠️ 抖音是字节「围墙花园」，通用检索对它的评论区索引极差，不刻意定向会「名挂抖音、实无抖音数据」。**每轮必须显式打抖音原生源。**
   - 抖音热搜榜：抓 `https://hotdata.aipromptnav.com/douyin/`（⚠️ JS 渲染，抓不到条目就搜 `抖音热搜榜 今天`、`抖音热榜 实时`）。
   - 定向检索（年月用 `--month` 动态取，**禁止写死**）：`抖音 热梗 <当前年月> 评论区`、`抖音 XXX梗 神评论`、`抖音 都在玩 什么梗 <当前年>`、`抖音 二创 爆火 梗 <当前年月>`。
   - 抖音原生梗示例（仅理解形态，⚠️ 可能过时禁止照抄，以运行时检索 + 档案「最近活跃」为准）：「我的刀盾」（What the dog doing 空耳）、「26 版《西游记》职场剧」（唐僧「规划个嘚儿」、悟空「我求你救我了吗」）。
   - 抓到热搜条目后，**必须回评论区验证「群众真在玩」**（A 级）或拿到媒体引述的真实抖音样本（B 级），不能只列热搜标题。

1. **主判定（必查，最高权重）**
   - 评论区：`抖音 评论区 热梗 <当前月>`、`B站 评论区 都在玩 什么梗 <当前年>`、`XX梗 评论区 复读 / 盖楼 / 回复 接龙`。重点看高赞评论、热评第一；**更重点看盖楼 / 嵌套回复链**——多人接力用同一句式对线，是「群众真在玩」最精准信号。
   - 弹幕：`B站 弹幕 刷屏 句式`、`主播名 嘴硬 弹幕 满屏`。名场面弹幕集体复读 = 最强「群众在玩」信号。

2. **已过滤精选参考（候选池补充）**：B站「梗指南」「KPL梗指南」「游戏梗指南」类盘点账号本周内容——它们已在筛选，但务必回评论区确认群众真在玩，不能只有账号自己在盘点。

3. **辅助阵地（交叉验证 / 找串子梗）**：虎扑步行街亮区、贴吧热门吧、NGA、游戏区。关键词：`虎扑 步行街 热梗`、`NGA 本周 梗`、`贴吧 热梗 <当前年>`、`电竞 嘴硬 名场面`。

4. **精选池详情（主引擎）**
   - **梗图网 gengtu.net**：抓 `https://gengtu.net/memes/origins/` 热梗索引（简介 + 梗图数做热度参考）；候选进一步抓详情页 `https://gengtu.net/memes/origin/<slug>/`——① 起源自带外部来源链接（可溯源，直接当「来龙去脉」出处）；② 「识别点 / 常见衍生」常直接列出评论区句式（如「豪到我了」），作用法实证线索；③ 站内梗图带真实评论截图引用。**重点看起源描述是否标「源自 XXX 评论区 / 神回复 / 接龙」——那是「评论区原味梗」的直接信号。** ⚠️ **该站可能 403 反爬**（部分网络环境实测拒抓）：抓不到就跳过，用萌娘百科 + B站盘点双源起步，别硬试。
   - **萌娘百科（主播 / 电竞圈梗强源，实测救场）**：`https://zh.moegirl.org.cn/` 检索主播 / 电竞 / 弹幕句式词条（如炫神「厕所踩头」「已取餐」、大司马「第五层」）——词条常**直接记载弹幕原句**，是主播嘴硬 / 电竞圈梗最省力的 B 级来源。可用 MediaWiki 接口：`https://zh.moegirl.org.cn/api.php`（搜 `action=opensearch`）。⚠️ **实测经验：泛词检索（"主播"/"电竞"）基本无效，必须用具体人名 / 主播名 / 游戏名（如「看海」「卢本伟」）才出词条。**
   - **贴吧热议接口（实测性价比最高的硬数据源，Deep 档必打）**：`https://tieba.baidu.com/hottopic/browse/topicList`（JSON，30 条带讨论量）——一次抓取直接实锤破圈梗（实测：野生狗奶 86 万、嘉豪 65 万讨论量）；虎扑 `https://www.hupu.com/`（步行街热帖带亮 / 回复）；AcFun `https://www.acfun.cn/`（二次元 / 抽象圈，评论区弹幕活跃）。
   - 纪律：小站证据 = 阵地名 + 硬指标（浏览量 / 梗图数 / 讨论量 / 亮回复数），不拿孤例当实证；属 B 级证据一部分，不单独构成 A 级；仍要回大站找媒体引述 / 弹幕硬数据呼应。

> 检索词年月一律用 `python scripts/week_window.py --month` 动态取，**禁止写死具体年月**（skill 长期用，9 月跑用 9 月）。多换关键词，覆盖「梗名」「事件」「主播名」「评论区在玩」等切入点。

### Step 3 — 按规则筛选（详见 references/filtering-rules.md）

加载 `references/filtering-rules.md` 逐条过筛，要点：

- **两级证据任一达标即收**：A 级 = 真实抓到评论区 / 弹幕 / 盖楼原句（浏览器或用户提供）；B 级 = 联网检索多源（≥2 阵地）确认「正在被大量玩」+ 可引用真实样本（媒体引述原句 / 播放弹幕硬数据），注明出处与「非实时抓取」。**绝不为凑 A 级编造原句 / 盖楼。**
- **收**：有固定句式 / 可二创、评论区 NOW 仍在玩（不限首发）、串子向、≥2 阵地有传播证据。
- **剔**：温和无害、纯新闻 / 纯热搜、微博系、小红书营销号、只有曝光没群众玩、无法溯源且无佐证。
- **老梗区分**：✅ 首发早但 NOW 仍在复读的活梗照收（来龙去脉注明真实首发时间）；❌ 纯翻新（换壳复读、无新玩法、评论区没真玩）剔除。
- 搜不到可靠出处的标「来源存疑」，**绝不编造来历或评论**。

### Step 3.5 — 同步到「持续累积档案」（核心机制）

- **位置**：工作区根目录 `热梗库/` 是统一产出库——住着 `热梗档案.md`（累积武器库）+ 每期周报（`热梗周报_YYYY-MM-DD.md`）。**每次运行最开始就读档案**，拿到已收录梗名做去重基准。
- **更新日志区**：档案头部「更新日志」表（日期 | 新收录 | 再次活跃）每次运行追加一行——新收录 = 本次搜索的成果，再次活跃 = 历史档案的迭代延续。
- **去重比对**（归一化梗名：去空格 / 标点 / 大小写）：新梗追加（填首次收录 + 最近活跃 = 今天）；已有梗只更新「最近活跃」，可补「再次活跃」备注。
- **条目格式**（与周报精简风格对齐）：

```
## 梗名
- **含义**：（一句话，50 字内，点出情绪 / 嘲讽对象 / 为什么爱玩）
- **来龙去脉**：（2-4 行：出处 + 真实首发时间 + 传播 + 当前活跃证据；搜不到标「来源存疑」）
- **【评论区 / 弹幕用法实证】**：（真实原句/盖楼，或媒体引述/硬数据并注出处与「非实时抓取」；绝不编假）
- 最近活跃：YYYY-MM-DD（机制字段，供去重与取数）
```

> 首发时间并入来龙去脉；证据等级体现在用法实证标注（A=实时抓取，B=非实时抓取/媒体引述）；首次收录由更新日志区记录；只有「最近活跃」是必需机制字段。
> **纪律**：档案只装「大量在玩」的梗（A / B 级达标），纯曝光不进——档案是「串子武器库」，不是「热搜垃圾桶」。

### Step 4 — 分级 + 排序 + 精选

- 三档：破圈级 / 发酵中 / 冷门趣味；档内按热度排（评论区复读广度、弹幕刷屏强度、跨阵地数量）。
- 取数：本轮新收录 + 档案「最近活跃」落在观察期内的条目；纯历史沉淀可留档不进本期。
- 速览目录分两组：🆕 本期新发现（本轮新收录）/ 🔄 档案延续（历史收录仍在玩）。
- 总数 **10–15 个（Deep 档可到 15–20），宁缺毋滥**——**检索先努力集齐 10 个以上有实证的梗再动笔**（档案已有实证的也算）；不足 10 个才允许少写，且报告剔除项里要说明「缺在哪、为什么凑不满」。只收评论区有群众在玩的梗，**绝不为了凑数降标**收「只有盘点标题、无实证」的梗。

### Step 5 — 按格式产出（见 references/output-format.md）

- **产出位置（硬规则）**：写入 `热梗库/热梗周报_YYYY-MM-DD.md`（同日多期加后缀）。**绝不写到别处**——热梗库是唯一产出落脚点。
- 标题下注明活跃观察期、主阵地、筛选标准；每梗含 梗名 / 含义 / 来龙去脉 / 【评论区 / 弹幕用法实证】（核心字段，原句即用法，**B 级原句即可，A 级可遇不可求**——能贴盖楼更好，没有不强求，绝不编）；来历不明标「来源存疑」；末尾加「本周梗风格总结」+「剔除项（含原因）」。

### Step 6 — 自检（发布前必做）

- [ ] 每个梗评论区 / 弹幕 NOW 都在玩？老梗已注明真实首发时间、纯翻新已剔？
- [ ] 无温和无害 / 微博 / 小红书营销号内容？
- [ ] 每个梗都有「评论区 / 弹幕实证」？只有曝光的「被报道的梗」已剔？
- [ ] 来源存疑都已标注，无编造来历 / 评论？
- [ ] 总数 10–15（Deep 档 15–20）？检索是否努力集齐 10 个以上有实证的梗？有没有为凑数收「无实证」的梗？
- [ ] **成本在预算内？**（检索次数 ≤ 档位上限、每梗 ≤2 阵地、档案实证 0 检索、失败已跳过）
- [ ] 档案已同步（新梗追加、已有梗更新「最近活跃」、无重复）？更新日志已追加一行？
- [ ] 用法实证给了真实原句（非编造例句）？优先抓了盖楼片段？原句能直接抄去用？

## 重要纪律（不可违反）

1. **绝不编造**：梗的来历、含义、评论样本必须真实；来历不明标「来源存疑」或舍去。
2. **抖音 + B站为主**：微博、小红书营销号推动的娱乐圈内容一律排除。
3. **串子口味优先**：温和无害主动剔除；优先对线 / 嘴硬 / 阴阳怪气 / 电竞游戏圈。
4. **长窗软约束**：不卡首发时间——NOW 仍在玩的活梗照收（注明真实首发）；只剔纯老梗翻新。
5. **两级证据任一达标即收**：A 级（实时抓取）或 B 级（多源确认 + 可引用样本）；只有两级都达不到的纯曝光才剔。**绝不为了凑「评论区实证」编原句 / 编盖楼。**
6. **宁缺毋滥**：10–15 个精选（Deep 档可到 15–20）——检索先凑满 10 个有实证的，凑不满才少写并说明；绝不硬凑无实证的。
7. **产出归位**：周报只写 `热梗库/`，档案同步更新，文件不散落。
