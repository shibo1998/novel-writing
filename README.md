# novel-writing

> 一个可安装的**中文长篇网文创作插件**。装上之后，对 agent 说一句「我想写一本小说」，
> 它就用对话带你从建文件夹一路走到逐章写作与一致性校验。

## 装

```bash
python scripts/install.py --list                     # 看本机有哪些 harness
python scripts/install.py --target workbuddy         # 装到用户级（跨项目可用）
```

支持 WorkBuddy / CodeBuddy / Claude Code / ZCode / Cursor / Windsurf，
也支持 `--dir` 装到任意技能目录。**纯 Markdown + 纯标准库 Python，无依赖。**

## 用

装完重开一个会话，然后：

```
我：我想写一本小说
```

agent 会问你：书名、放哪、题材、平台、单章字数、有没有样板书——
然后一条命令把整本书的骨架建出来（目录、配置、运行守则、工具，全自动）。

接着它让你选下一步：**拆样板书** / **先做世界观** / **先写探索草稿**。

> 想先动笔？走**探索草稿**（`tools/draft.py`）：试写稿落在 `drafts/`，标记为非正典，
> 不进 `chapters/`、不推进状态、不写账本。正式章节一律要求正典、细纲、账本就绪——
> 写前接地缺资料会直接失败，不会空转。

已经有一本书了就说：

```
我：继续写《高武》
```

它会定位到书、读正典、生成写前接地单，然后按流程写。

## 它凭什么让长篇不崩

长篇最大的敌人是**漂移**——写到第 30 章，人物名、数值、时间线各自长出一套。

这个插件用三层挡它：

| 层 | 做什么 |
|---|---|
| **正典速查表**（`canon.md`） | 写作时的唯一事实来源；关键值一律从表里取，不凭印象 |
| **六个校验工具** | 单章对账、状态同步、跨章账本、写前接地、出章闸门、后台监视 |
| **人工门禁** | 每章停下等作者确认，**禁止连续生成多章** |

其中「跨章账本」是别处很少见的：单章检查只看章内写法，状态检查只数章数，
**两者都看不见"章与章之间的账"**——上一章攒到 19 点、下一章凭空变成 32 点，
这类断裂靠它才拦得住。它还能从当前余额**投影出"哪天攒够破境"**，
和细纲里写死的日期比对，**在写那一章之前好几章就发现排期对不上**。

## 设计原则

1. **代码通用，配置项目级。** 工具代码里不含任何一本书的内容；随书变化的值全在
   `<书>/.soloent/book.json`。
2. **单一来源。** 同一个值只允许存在一处。
3. **可推导的交给脚本，不可推导的留人工标记位。** 能算的（加减乘除、单调性、章号连续性）
   机检；不能算的（这一章实际写了什么）交给写前接地单 + 每章一停。
4. **失败关闭。** 闸门抓不到机检结果时判未通过，不默认放行。

## 目录

> 支撑目录沿用 **SoloEnt 官方约定**：`templates/` · `docs/` · `scripts/`。

```
novel-writing/
├── SKILL.md              入口（agent 读这个）
├── scripts/              工具真身 + 初始化 + 安装 + 自检 + 打包
├── docs/                 分阶段手册（00 总览 … 13 版本控制，按需加载）
├── templates/            新书骨架模板
│   ├── SOLOENT.md        中央控制面板（8 板块）
│   ├── canon.md          正典速查表
│   ├── ledger.tsv        章节账本
│   ├── now.md            活跃写作状态（含机器可读状态块）
│   ├── relations.md  world-rules.md  roadmap.md
│   ├── story-style.md    本书专属规则
│   └── MASTER.md         创作宪法
├── assets/               打包进来的库与配置模板
│   ├── rules/            规则库（13 个；逐条清单见 docs/09-规则清单.md）
│   ├── skills/           技能库（13 个：三连、设定、拆书、开篇审核、发布、角色沙盘…）
│   ├── workflows/        工作流（7 个：世界观/大纲/角色/润色/审查/卡文/诊断）
│   ├── book.example.json 配置模板
│   ├── AGENTS.template.md 运行守则模板
│   └── hooks.config.example.json
└── hooks/                可选钩子（自动注入正典与状态、章节落盘自动对账）
```

> 部分 harness（如 WorkBuddy / Claude Code）的技能约定把支撑目录叫 `references/` 与 `assets/`。
> 名称只是约定——`SKILL.md` 里按**显式路径**引用支撑文件，两套命名都能正常工作。

## 更新

```bash
python scripts/sync.py --all --lib "<作品库根目录>"   # 改完模板/配置后刷新所有书
python scripts/selftest.py                            # 怀疑工具没生效时（检查项会不会触发）
python scripts/audit.py                               # 改过模板/技能/文档后（各部分对不对得上）
python scripts/bundle_vault.py --vault "<writing-vault>"  # 重新打包规则与技能
```

**插件挪了位置 → 跑一次 `sync --all`**（各书的薄壳里存的是插件的绝对路径）。
