## ⛔ 为什么必须"禁载"

`assets/rules/` 是**全量库，不是"应加载集合"**。
里面**含互相冲突的题材规则**——把整个目录喂给 agent 会出事。

真实的冲突例子：

> `style-xianxia.md` 要求「禁止现代口语和网络梗、对话须有古韵」，
> 与都市高武类项目的主角人设**直接打架**。

所以 `book.json` 里除了 `rules.load`，还有 `rules.forbid` + `forbid_reason`：

```json
"forbid": [
  "active-plugin-rules/style-xianxia.md",
  "active-plugin-rules/style-farming.md",
  "active-plugin-rules/style-creative.md",
  "_removed/style-historical.md"
],
"forbid_reason": "仙侠要求禁现代口语、种田是慢节奏、脑洞是设定前置写法，均与本书冲突"
```

**禁载清单会渲染进 `AGENTS.md §2`**，agent 每次开工都看得到。
`init_book.py` 会根据你选的 `--tags` **自动生成**禁载清单——没选的标签自动进 forbid。

## 怎么做到"按风格自动触发"

**不是让 agent 每本书临场判断**（判断会飘，同一本书不同会话结果可能不一致），
而是**写死在配置里**：

1. `init_book.py` 按 `--tags` 生成 `rules.load` 与 `rules.forbid`
2. `sync.py` 把它们渲染进 `<书>/AGENTS.md §2`
3. agent 打开书目录 → 读 `AGENTS.md` → 只加载清单里那几条

## 三类内容的触发方式（沿用 SoloEnt 约定）

| 类型 | 触发方式 | 在本插件里 |
|---|---|---|
| **Rule** | **自动生效**，无需手动调用 | 由 `book.json` 的 `rules.load` 声明，渲染进 `AGENTS.md §2`，agent 每次开工按清单加载 |
| **Workflow** | **命令 / 点名触发** | 用户说「走一遍三层大纲」「卡文了」时，读对应文件执行 |
| **Skill** | **按场景自动触发** | 描述匹配到就用；也可显式点名（「用 humanizer-webnovel-cn 润色本章」） |

> 这就是为什么 `rules.forbid` 必须写死：**Rule 是自动生效的**，
> 加载了冲突的题材规则，agent 会不声不响地按它写。

## 这批资产从哪来

`assets/rules/` 与 `assets/skills/` 由 `scripts/bundle_vault.py` 从用户的 `writing-vault`
（灵蟹创作编辑器的插件与规则备份）打包而来，来源与时间记录在 `assets/_bundle.json`。

要更新：

```bash
python "<插件>/scripts/bundle_vault.py" --vault "<writing-vault 路径>"
```

⚠️ **不要手改 `assets/rules/` 与 `assets/skills/` 下的文件**——下次打包会被覆盖。
要改就去改 `writing-vault`，或把本书专属的改动写进 `.soloent/rules/story-style.md`。
