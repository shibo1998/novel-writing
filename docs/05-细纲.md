# 05 · 细纲（章纲）

## 这一层要细到什么程度

**细到"照着重写就行"，但不要细到"把正文写完了"。**

每章 3–5 行，写清：

1. **本章节拍**：按顺序发生哪几件事（分场景）
2. **章末钩子**：收在什么悬念/动作/未尽对话上
3. **涉及伏笔**：本章埋设/承接/引爆哪几条（对得上「伏笔回收总表」）
4. **涉及人物**：谁在场、谁不在
5. （可选）数值变化：本章收支、境界、故事日推进

## 细纲格式

`brief.py` 支持两种写法，由 `book.json` 的 `chapter.outline_format` 决定（默认 `auto` 自动探测）：

**inline** —— 一行一章，紧凑：

```
31 集训结束返校：许昂走廊堵人放话｜钩子·对白炸弹：许昂说漏了父亲的名字
```

**heading** —— 分块，能放更多：

```markdown
## 第31章 集训结束返校

**核心概括**：集训终期考核后返校，许昂在走廊堵人放话，说漏了父亲的名字。

**章末钩子**：对白炸弹 —— 许昂说漏了父亲的名字
```

两种都能被 `brief.py` 解析出来，写前接地单里会直接摆出来。

## 与伏笔表联动

细纲里出现"埋/接/爆"某条伏笔时，**同时在 `outline/伏笔回收总表.md` 里更新那一条的章节号**。
`brief.py` 按章号筛伏笔表，只认表里的数字——细纲写了但表里没登记，接地单就不会提醒你。

## 细纲是"活"的

写正文时发现细纲不对，**不要硬写**。停下来报告：

> 本章细纲计划 X，但按上一章的实际状态只能 Y。要不要调整细纲？

调整后：
- 改细纲
- 若影响到后续章，同步改
- 在 `notes/` 留档（骨架层变动纪律）

**禁止**"先按细纲写完，后面再圆"——那正是漂移的起点。

## 检查点

细纲写完后，可以拿它和 `book.json` 的配置对一遍：

```bash
python tools/brief.py 31      # 看接地单能不能正确解析出本章节拍
```

如果 `brief.py` 报"细纲中未找到第 N 章条目"，说明格式或路径不对——先修这个，再动笔。

## 完成后

停下等确认。确认后进 `06-正文.md`，开始每章循环。
