# 07 · 审查与修订

## 四种审查，别混为一谈

| 层级 | 频率 | 怎么跑 | 管什么 |
|---|---|---|---|
| **单章对账** | 每章 | `python tools/preflight.py` | **硬伤**：正典冲突、数值矛盾、悬空设定、句长节奏、标点 |
| **`/review` 五层审查** | 每章 | `/review`（`assets/workflows/chapter-review.md`） | **质量**：一致性、风格、钩子、结尾陷阱、AI 写作模式 |
| **阶段审查** | 每卷 / 每 10 章 | 同上，但拉长视野 | 结构、爽点密度、追读性、卷目标是否达成 |
| **黄金三章审核** | **开篇专用（前 3–5 章）** | `assets/skills/golden-three-chapters-review/SKILL.md` | 开篇吸引力：切入点／金手指／代入感，**10 维度 10 分制**（标准见其 `docs/STANDARDS.md`） |
| **`/market` 发行诊断** | 全书写完 / 接近完成 | `/market`（`assets/workflows/publishing-diagnosis.md`） | 类型定位、卖点、可比书、出版路线 |

### ⚠️ 顺序不能反

**先过闸门（硬伤清零），再跑 `/review`（质量评审）。**

| | 管什么 | 性质 |
|---|---|---|
| `preflight.py` | 能算出来的（人名、数值、章号、句长分布） | **机检**，失败关闭 |
| `/review` | 需要判断的（追读性、钩子质量、角色声音、AI 味） | **评审** |

在有硬伤的稿子上做质量评估，等于白评。

## `/review` 的五层（官方定义）

1. **基础审查** —— 字数是否符合目标；是否遵循细纲
2. **一致性审查** —— 故事连续性（对大纲/幕结构）、章节流向（对上一章）、角色完整性（对人设档）、世界规则（有无违反已建立设定）
3. **写作风格审查** —— 风格指南合规（对 `SOLOENT.md §5` / `.soloent/rules/story-style.md`）、角色声音、基调一致性
4. **章节结尾审查** —— 钩子质量、**结尾陷阱**（重复用词 / 过长内心独白 / 软弱结尾）、与下一章的过渡
5. **AI 写作模式检测** —— 原创性、重复短语、**破折号过度使用**、**"词、词、词"列表模式滥用**

**产出**：`notes/review-chapter-{章号}-{日期}.md`

> 官方建议：**每章完成后、进入下一章之前跑一次**——问题在更容易修的时候就被发现。
> 本插件的 `preflight.py` 覆盖了第 1、2 层的**可机检部分**；第 3、4、5 层需要 `/review`。

## 单章对账（每章自动做）

已经在 `06-正文.md` 第 6 步。产出在 `notes/对账-YYYY-MM-DD.md`，按严重度分三档：

| 档 | 含义 | 处理 |
|---|---|---|
| **严重** | 硬伤：正典冲突、情报泄露、标点违规、句长节奏崩了 | **必须修，闸门会拦** |
| **中等** | 需人工判定：刻度可疑、超长章、对话占比过高 | 看一眼，确认无误就加进豁免 |
| **轻微** | AI 句式黑名单词逐行报点 | 累计 > 60 触发警告，单章 > 阈值也警告（**不拦截**） |

### 豁免机制

有些报警是**误报**（同句并列了两个不同对象的数据、机检就近挂错了档位）。
确认无误后加进 `book.json` 的 `checks.scale_exempt`：

```json
"scale_exempt": [
  ["ch-11.md", 199, "20 是 F 段门槛，E⁻ 是同句目的地，两者并列非冲突"]
]
```

**理由要写。** 这不是"静默忽略"，是"人工核验后留档"——下次别人看到这行知道为什么放它过。

## 正文润色

用 `assets/workflows/prose-polishing.md`，或单独点名 `humanizer-webnovel-cn`。

**润色的边界**：润色是改"怎么说"，不是改"说了什么"。
不得增加人物、事实、线索、事件、数字，不得改变选择和后果。
一旦越界，那就不是润色而是改剧情——要走骨架层留档。

## 修订的纪律

- **改一处，同步全部受影响档案。** 改了人物名 → `canon.md` + `book.json` 的 `name_bad` + `characters/`；
  改了数值口径 → `canon.md` + `book.json` 的 `scale`/`income` + `ledger.tsv` 相关行。
- **改完当天在 `notes/` 留档**（日期 + 原因 + 影响范围）。**未留档的变动视为未发生。**
- 改完跑一遍全量对账确认没有新伤：

```bash
python tools/consistency_check.py     # 全量
python tools/ledger.py                # 跨章账
python tools/preflight.py             # 闸门
```

## 废稿与归档

- 作废的正文/设定归档到 `notes/archive-<原因>-<日期>/`。
- **归档内容不得作为剧情正典引用。**
- 但**不要直接删**——已验证的文本资产（台词、场景、留白动作）可能还能迁移复用。

## 卡住了怎么办

用 `assets/workflows/brainstorming.md`（卡文助手）。

另外先检查一件事：**是不是 `canon.md` 和实际正文已经不一致了？**
很多"写不下去"其实是前面某章的设定漂移导致后面无路可走。
跑一次全量对账往往就能定位。
