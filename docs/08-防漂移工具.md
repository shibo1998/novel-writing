# 08 · 防漂移工具

## 为什么需要这一层

「前后不连贯」里，**有一半是可以算出来的**（加减乘除、单调性、章号连续性、句长分布），
另一半算不出来（这一章实际写了什么）。

这一层的设计原则：**可推导的交给脚本，不可推导的留一个需要人主动动作的标记位。**

| 谁管 | 管什么 |
|---|---|
| `consistency_check.py` | **单章内部**的写法 |
| `state_sync.py` | 进度**条数**（写了 N 章，进度写了 N 吗） |
| `ledger.py` | **章与章之间的账**（前两者都看不见的那一层） |
| `brief.py` | 写前把事实摆到眼前 |
| **每章一停** | 作者过目 —— 唯一能判断"好不好看"的一环 |

## 六个工具

### `brief.py` —— 写前接地单

```bash
python tools/brief.py [章号]      # 缺省＝下一章
```

打出五节：细纲节拍 / 本章数值台账 / 相关伏笔三态 / 当前进度 / 正典速查。

**为什么需要它**：「记忆丢失」不是模型把事忘了，而是它**凭印象写**。
印象来自上下文里的残影，文件里才是事实。跑一次，事实重新进入上下文。

### `consistency_check.py` —— 单章对账

```bash
python tools/consistency_check.py --list-checks   # ★ 机检项清单（唯一来源，文档不复述）
python tools/consistency_check.py --suggest-rhythm  # 按实测给句长节奏阈值（只读，不写文件）
python tools/consistency_check.py --suggest-rhythm --from 1-边界  # 按样板书校准（更准）
python tools/consistency_check.py                # 全部正文
python tools/consistency_check.py ch-08 ch-10    # 指定章
```

产出 `notes/对账-YYYY-MM-DD.md`，每条带行号与摘录。

> **机检项清单以 `--list-checks` 输出为唯一来源。** 任何文档都不要复述这个清单——
> 复述了就会和代码漂移。这是本层的纪律之一。

### `state_sync.py` —— 状态同步校验

```bash
python tools/state_sync.py          # 校验，不一致退出码 1
python tools/state_sync.py --fix    # 自动修「可推导字段」
```

原理：`now.md` 顶部有一个机器可读状态块：

```
<!-- SOLOENT-STATE
chapter: 30
story_time: 高二上 · 集训终期考核后
location: 临江 · 青峰山集训基地
narrative_verified: 30
updated: 2026-09-18
-->
```

- `chapter` —— **可机器同步**，`--fix` 会自动对齐
- 其余字段 —— **叙述性字段**，必须人工/AI 回写
- `narrative_verified` —— **人工确认戳**：把叙述性字段都补好后改成本章号

> ★ `--fix` **不会碰** `narrative_verified`。所以跑 `--fix` 无法绕过这道——
> 它防的正是「章节号修好了、状态其实是旧的」。

另外它会用内容 sha256 基线检测「正文在上次核对之后又被改过」。

### `ledger.py` —— 跨章账本对账

```bash
python tools/ledger.py            # 全量 + 破境投影
python tools/ledger.py --quiet    # 只输出结论（供闸门调用）
```

它管什么（可推导）：
1. 有章必有账（**这一条最要命**）
2. 重号与缺口
3. 余额平账
4. 收入合法（不超过 期数 × 速率）
5. 境界单调（不倒退）
6. 突破成本
7. 故事日单调
8. 时间空档（跨了 N 天却没记够收入）
9. **破境日投影** —— 从余额推"哪天攒够"，与细纲写死的那天比对

每一项都由 `book.json` 的 `ledger` 区块开关；没配置的自动跳过。

> **它不管**：这一章实际写了什么。那一半交给 `brief.py` 与每章一停。

### `preflight.py` —— 出章闸门

```bash
python tools/preflight.py
```

汇总上面三个，再加**批量长跑检测**、**流程留痕校验**与**上一章评审校验**。**判定纪律**：

- **流程留痕**：`now.md` 里必须有本章的 `[流程] ch-N 自查X 三连Y 复查Z 回写OK` 行，**且与机检残留对撞**。
  前四项验的只是「算得出来的东西」，而**句法自查／技能三连／连续性复查算不出来**；
  但「这几步真跑过」会留下一个**可机检的影子**：机检能看见的那几类 AI 味残留应当已清零。
  所以闸门做两件事——① 格式层：缺失、格式非法、标注「未执行／跳过／历史章」一律**拦截**；
  ② 对撞层：本章仍有黑名单词／句式禁项／同段连发／比喻堆砌／章末升华／面板条目残留，
  又没在行尾写明「保留：<理由>」→ **拦截**（确需保留的降为警告，交 /review 复核）。
  这条是 2026-09-20 补的：此前只验格式，69 章留痕全写 `自查0 三连0 复查0` 却残留 63 处黑名单词，
  格式合法成了伪造的通行证。
- **上一章评审**：第 7 步（`/review`）不再是"靠自觉"。出第 N 章时，闸门要求
  `notes/review-chapter-<N-1>-<日期>.md` 已存在（`gate.review_required` 开启时；新书由 `init_book` 默认开启）。
  实测某书 69 章的评审产物数为 **0**——SKILL 写着"跳过 = 正文只过了半关"，那一半从没跑过而无人发现。
  `--chapter N`（批量补验历史）不受此项约束：补验是恢复旧校验点，不是发布新章。
- **失败关闭**：抓不到机检摘要行（脚本报错 / 被中断 / 输出格式变了）一律判未通过，**不默认放行**。
- **校验点只前进不后退**：章节目录为空时不会把 checkpoint 写回小值。
- 新书（0 章）会明确说"无章节可校验"并放行，同时提醒"若原本有章节请检查是否误删"。

### `watch_and_check.py` —— 后台监视

```bash
python tools/watch_and_check.py              # 前台
powershell -ExecutionPolicy Bypass -File tools/start_watcher.ps1   # 后台
powershell -ExecutionPolicy Bypass -File tools/stop_watcher.ps1
```

轮询 `chapters/`，一有改动就自动过闸，写进 `notes/对账日志.md`。
纯标准库，不需要装 watchdog。**与 agent 是否守流程无关。**

> **编排约定**：钩子与 watcher 都**只调用 `preflight.py` 一次**（`--tag` 区分入口报告，
> `--since` 增量扫描正文，账本/状态仍全量），不再各自预跑对账——否则一次保存触发
> 两遍全书扫描，且共享的当日报告会互相覆盖。preflight 全程持项目锁
> （`.soloent/locks/`），多入口同时触发时串行执行；锁被占用时自动入口**跳过本轮并
> 保留基线**（退出码 3，「跳过 ≠ 通过」，下轮自动重查）。报告、趋势 CSV、状态哈希
> 均为「锁 + 原子替换」写入，不会留下半截文件。

## `doctor.py` —— 系统体检（只读，自动跑）

它回答一个问题：**「防护是不是真的在生效？」**

钩子失效、薄壳缺失、Rule 没部署这类**配置漏配平时毫无症状**，
等发现时防护早就不在了 —— 而指望人主动想起来跑体检，等于永远不会跑。
所以它挂在 **SessionStart 钩子上自动执行**，**只在发现问题时才注入提示，全绿时完全不出现**。

查什么：

| 范围 | 项 |
|---|---|
| 插件本体 | `scripts/` `hooks/` 是否齐、`SKILL.md` 在不在 |
| 已装副本 | 与源是否一致（只查**真装过**的 harness） |
| 每本书 | 五件套齐不齐 · 章号连不连续 · 校验点/now.md/正文三者是否对齐 · 正文与基线是否漂移 · 钩子路径是否绝对路径且文件存在 · watcher 进程是否还活 · 生成物是否漂移 · Rule 是否按 `rules.load` 部署 · 账本是否覆盖各章 |

```bash
python tools/doctor.py                          # 体检当前书（全量）
python tools/doctor.py --lib "D:/1-work/novel"  # 体检每一本
python tools/doctor.py --quick                  # 只查硬项（会话启动时自动用的就是它，<1s）
python tools/doctor.py --fix                    # 只清理死掉的 watcher.pid
python tools/doctor.py --json                   # 机器可读
```

**安全性**：只读。`--fix` **只做一件事**——删掉已经死掉的 `watcher.pid`；
正典、正文、配置一律不碰。它**不接进闸门**，所以**不会影响出章流程**。
体检自己出任何异常都静默跳过，绝不拖累会话开场。

> ⚠️ **写体检项的铁律：不许自证。**（2026-09-19 实测教训）
>
> 当时 `check_hooks` 只验「配置存在 ＋ 路径是绝对路径 ＋ 脚本文件在」，
> `check_watcher` 只读 `watcher.pid` —— **两项都报绿**，而实际情况是
> **钩子从未触发过、watcher 一直在跑**。根因是「用配置自证」：
> 拿插件自己写的那套 schema，去证明插件自己没问题。
>
> 结果就是本文件开头要防的那件事：**「等发现时防护早就不在了」——而体检还在说一切正常**。
>
> 现在这两项的 ok 分支都改成验证**外部真实状态**：
> `check_hooks` 先判「当前 harness 认不认这个配置路径」，
> `check_watcher` 改为**按进程扫**（pid 文件降为辅助，它会在插件更新/强杀时丢）。
>
> **规矩**：任何 ok 分支都必须能回答「你凭什么说它好了」——
> 凭进程在跑、凭 harness 会读、凭实跑通过，而不是凭「文件在那儿」。

## `audit.py` —— 插件自审计（只读）

`doctor.py` 体检的是**某一本书**；`audit.py` 审计的是**插件本身**——不需要有书。

它回答：**「插件的模板 / 技能 / 文档 / 脚本 / 生成物，五者互相对得上吗？」**

这类不一致**不会报错**，只会让 agent 读到过时路径、找不到文件、或按错的结构干活。
2026-09-19 靠它抓到两个真 bug（都是「文档写了、实现没跟上」型）：

- **生成物含未渲染占位符**：`sync.py` 给 `stop_watcher.ps1` 赋值时漏了 `.format()`，
  `{{` 原样落进每本书 → **PowerShell 语法错误，后台监视器停不掉**。
- **过时路径**：技能里 19 处 `.novelkit/`（上一代目录名）＋ 2 个脚本里的 `.novelkit/.api.env`
  → agent 照着读会去找一个不存在的目录。

```bash
python scripts/audit.py              # 全量（含建临时书实测生成物）
python scripts/audit.py --no-render  # 跳过实测，更快
```

| 代码 | 查什么 |
|---|---|
| A1–A3 | 模板：缺失 / 孤儿 / 占位符无对应渲染值 |
| B1–B2 | 技能：缺 `SKILL.md` / 内部引用断链 |
| C1 | docs 引用断链 |
| D1 | 脚本语法错误 |
| **D2** | **生成物含未渲染占位符**（真建一本临时书跑一遍再检查）★ |
| **D3** | **流程冒烟**：建书 → 造章 → 回写 → 过闸，验证主干路走得通 ★ |
| E1 | 孤儿技能（从未被主流程或 docs 引用） |
| **E2** | **过时路径**（上一代目录 / 文件名）★ |
| **F1** | **死字段**（`book.json` 的 schema 里有、但脚本没人读）★ |

**安全性**：只读。临时书建在系统临时目录，跑完即删。退出码 0 = 无问题，1 = 有问题。

> **什么时候跑**：改了模板 / 技能 / 文档 / 生成逻辑之后。
> 与 `selftest.py` 的分工——`selftest` 验「检查项会不会触发」，
> `audit` 验「插件各部分对不对得上」。

## 出问题了怎么排查

```bash
python "<插件>/scripts/selftest.py"     # 自检：注入故障验证每项检查真的会触发
python "<插件>/scripts/audit.py"        # 审计：插件各部分对不对得上（改过插件就跑）
python tools/doctor.py                  # 体检：防护是不是真的在生效
```

**为什么要自检**：真实书稿往往是干净的，跑出来 0 处问题——
**分不清是"检查通过"还是"检查没跑"**。自检在一本临时假书上注入已知违规，逐项断言。

若报"未触发"，说明那项检查坏了，先修插件再继续写。

## 工具在哪

- 书目录下的 `tools/` 是**薄壳**（由 `sync.py` 生成，**不要手改**）
- 真身在 `<插件>/scripts/`
- 改逻辑 → 改插件，所有书同时生效
- 改本书正典/数值/账本结构 → 改 `.soloent/book.json`

```bash
python "<插件>/scripts/sync.py" --root "<书目录>"          # 刷新一本书的生成物
python "<插件>/scripts/sync.py" --all --lib "<作品库>"      # 刷新全部
# 加 --check 只检查不写（定期核对用）
```
