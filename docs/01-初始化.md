# 01 · 初始化新书

> ⚠️ **先分清两件事，别混：**
>
> | | 是什么 | 命令 |
> |---|---|---|
> | **开新书** | 建整个项目：目录骨架 + 配置 + 工具 + 中央面板 | `init_book.py`（本页） |
> | **`/init`** | 生成或补建 `SOLOENT.md`（中央控制面板），**项目任意阶段可用** | `/init`（见 `12-命令与操作.md`） |
>
> 开新书时 `init_book.py` **顺带**把 `SOLOENT.md` 的骨架生成出来；
> 但 `/init` 是独立的能力——**书已经写了几十章、面板却过时或不存在时，就靠它补**。

## 你要问用户什么

一次性问完，不要挤牙膏：

1. **书名** —— 可先留「待定」
2. **小说文件夹放哪** —— 建议 `<作品库>/<书名>/`；文件夹名只用字母数字连字符下划线
3. **题材** —— 自由描述，如「都市高武 · 校园学院流」「仙侠玄幻 · 系统流」
4. **题材标签** —— 决定加载哪几条风格规则（见下表），可以按题材先推断再让用户确认
5. **平台** —— 番茄男频 / 起点 / 其他
6. **单章字数** —— 默认 2400
7. **篇幅目标** —— 如「100 万字以上」
8. **有没有样板书** —— 有的话建议先走 `02-拆书与边界.md`

## 题材标签对照

| 标签 | 适用 | 加载的规则 |
|---|---|---|
| `urban` | 现代都市 / 校园 / 职场等现实背景 | `style-urban.md` |
| `xianxia` | 修真 / 仙侠 / 东方玄幻 | `style-xianxia.md` |
| `system` | 主角有系统 / 面板 / 数值化金手指 | `style-system.md` |
| `farming` | 经营 / 建设 / 种田流 | `style-farming.md` |
| `creative` | 设定驱动 / 一文一大脑洞 | `style-creative.md` |

**通用 7 条所有书都加载**：`ai-anti-patterns` + `prose-directness` +
去 AI 味 4 条 + `style-webnovel-base`。不用问用户。

**常见组合**：

| 书 | 标签 | 合计规则 |
|---|---|---|
| 都市高武 + 系统 | `urban,system` | 9 条 |
| 仙侠 + 系统 | `xianxia,system` | 9 条 |
| 纯都市无系统 | `urban` | 8 条 |
| 种田经营 | `farming` | 8 条 |
| 脑洞设定流（都市背景） | `urban,creative` | 9 条 |

> ⚠️ **标签决定"禁载"清单**：没选的标签会被自动列进 `rules.forbid`，
> 并写明理由（"XX 与本书题材不匹配"）。这是"按风格自动触发"的实现方式——
> 写死在配置里，不靠 agent 每本书临场判断。

## 跑初始化

```bash
python "<插件目录>/scripts/init_book.py" \
  --dir "D:/1-work/novel/我的新书" \
  --title "我的新书" \
  --genre "都市高武 · 校园学院流" \
  --platform "番茄男频" \
  --tags urban,system \
  --words 2400 \
  --length "100 万字以上"
```

**它会生成什么**：

```
<书>/
├── SOLOENT.md             ← ★ 中央控制面板（8 板块），随创作逐步填充
├── .soloent/
│   ├── book.json          ← 唯一需要你维护的机器可读文件
│   ├── canon.md           ← 正典速查表（值的事实来源）
│   ├── ledger.tsv         ← 章节账本
│   ├── constitution/MASTER.md   ← 创作宪法（红线）
│   ├── memory/
│   │   ├── now.md         ← 活跃写作状态（含机器可读状态块）
│   │   ├── relations.md   ← 关系网络
│   │   ├── world-rules.md ← 核心世界规则摘要
│   │   └── roadmap.md     ← 路线图与里程碑
│   └── rules/story-style.md  ← 本书专属规则
├── AGENTS.md              ← 运行守则（**渲染生成，不用手写**）
├── tools/                 ← 8 个薄壳（**生成，不用手写**）
└── chapters/  characters/  world/  outline/  notes/  review/  1-边界/
```

加 `--json` 拿结构化摘要（便于程序化处理）。

## 关于 SOLOENT.md

它是**中央控制面板**，不是可有可无的说明文件。长篇写作的上下文漂移问题靠它解决——
每次开工 agent 先读它，就知道这本书是什么、规则是什么、文件在哪、写到哪了。

**8 大板块**（摘要留这里，细节存分档）：

| 板块 | 生命周期 | 谁更新 |
|---|---|---|
| 1. 项目 DNA | 初始化时一次 | 用户 |
| 2. 世界系统 | 世界扩展时 | agent + 用户 |
| 3. 角色 | 添加角色时 | agent + 用户 |
| 4. 情节与结构 | 大纲更改时 | 用户 |
| 5. 风格指南 | 需要纠正风格时 | 用户 |
| 6. 关键约束 | 修订后 + 随时 | **agent（从反馈学习）+ 用户** |
| 7. 活跃写作状态 | **每章后** | agent（自动） |
| 8. 路线图 | 任务完成时 | agent（自动） |

`init_book.py` 只填它知道的（书名/题材/平台/字数），其余留空——**在商讨阶段随创作填**。

> ⚠️ **第 7 部分过时是最常见的陷阱。** 写了 3 章却没更新状态，AI 就会在你实际写到
> 第 8 章时写得像还在第 2 章。本插件用 `now.md` 的状态块 + 出章闸门强制这一条。
>
> ⚠️ **不要把世界观正文粘进 SOLOENT.md。** 摘要 + 指针，细节放 `world/`。

## 生成后必须停下

向用户报告建了什么，然后**让他选**下一步：

> **A. 拆样板书** —— 有对标作品就先拆它（推荐，产出可执行的写作边界）
> **B. 先做世界观** —— 设定已想清楚，直接从世界观与力量体系开始
> **C. 先写探索草稿** —— 已有想法，边写边补设定（走 `tools/draft.py`，试写稿落 `drafts/`，
> 非正典；转正须补齐正典/细纲/账本行并经作者确认）

不要替他决定。三个入口对应不同的手册。

> ⚠️ **没有「直接写正式第一章」这个入口。** 正式章节的前置资料（正典、细纲、账本行）
> 缺任一项，`brief.py` 都会拦截——试写想法请放进探索草稿，不要伪装成正式第 1 章。

## 常见问题

**Q：`book.json` 里一堆 `checks` 都是空的，要紧吗？**
不要紧，而且是**故意的**。初始化阶段还没有正典可查——人物没定、数值没定、细节没写。
等这些长出来再补（见 `00-总览与流程.md` 的「什么时候该回头补」）。

**Q：账本只有 `ch / day / note` 三列，够吗？**
够。它至少能查「有章必有账」和章号连续性——这已经能拦住最要命的那类断裂
（写了 5 章，账本只有 3 行）。等力量体系定了再加数值列。

**Q：能改书名/题材吗？**
改 `book.json` 的 `book` 段，然后重跑 `sync.py --root <书目录>` 刷新 `AGENTS.md`。

**Q：想在同一台机器上开好几本？**
可以。每本书的 `.soloent/` 完全独立。但**要把「具体某本书的目录」当工作区打开**，
不要把作品库根目录当工作区——根目录下没有明确的"当前书"。
