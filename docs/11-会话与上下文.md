# 11 · 会话与上下文管理

> 这一节管的是**比单章更大的单位**：一个会话能装多少、什么时候该开新窗口。
> 长篇写作崩掉的原因，一半是设定漂移，另一半是**上下文爆了还不换窗口**。

## 为什么上下文不是越大越好

官方手册给的三条理由，都成立：

| 问题 | 说明 |
|---|---|
| **注意力分散** | 过大的窗口会让模型注意力稀释，尤其在反复探索和修改时，性能反而下降 |
| **成本阶梯** | 部分模型按会话大小阶梯收费（如 256K 以上显著上涨）；缓存跨天或长时间间隔会失效，单次请求可能吃掉大量 token |
| **换模型更贵** | 单窗口积累到一定程度后换模型，新模型要读完旧模型积累的全部上下文——**切换前必须先总结** |

**建议把上下文上限控制在 200K–300K**，不要用满 1M。主流 Agent 产品（如 Codex Cloud）通常只用第一档。

## 两条阈值

| 阈值 | 该做什么 |
|---|---|
| **100–150K** | 在合适时机考虑**开新窗口** |
| **约 200K** | 继续使用可能带来**成本激增** |

> 不同 harness 的查看方式不同：SoloEnt 在对话框上方有进度条（如 `30.2k / 300.0k`）；
> 其他 harness 可能藏在设置里。**看不到就按章数估**——大约每章正文 + 工具输出占 3–8K，
> 10 章左右就该留意了。

## 任务隔离原则

> **一个会话只做一件事。任务完成后核对完成情况。**

下一件事跟当前任务**有关联**：先总结当前会话、**落地到项目文件**，再开新会话继续。
下一件事**关联性不强**：果断开新窗口，别让历史 token 堆着。

### 在本书流程里，"一件事"是什么

好消息：**「每章一停」本身就是天然的隔离边界**。所以：

| 场景 | 建议 |
|---|---|
| 日常逐章写作 | 一个窗口写 **3–8 章**，或到 100–150K 就换 |
| 卷末 / 大结构变更 | **单独开一个窗口**，别和逐章写作混在一起 |
| 拆样板书 | **单独窗口**（要读大量原文，很占上下文） |
| 设定/大纲讨论 | 讨论完**当天落盘**，别指望会话记得 |

## 开新窗口前：必做的交接

**这一步不做，新窗口就会从头猜起。**

```bash
# 1. 把状态落盘（这是最重要的一步）
#    · .soloent/memory/now.md —— 状态块 + 五个小节
#    · SOLOENT.md §7 / §8 —— 中央面板的摘要
#    · .soloent/ledger.tsv —— 本章数值行
python tools/preflight.py        # 确认闸门是绿的再走

# 2. 如果讨论了很多但没落盘，让 agent 先做一次汇总并写成文档
#    → notes/ 下，或直接并进 SOLOENT.md 的对应板块
```

**交接检查表**（逐项确认）：

- [ ] `now.md` 状态块与五小节已更新到最新章
- [ ] `SOLOENT.md §7` 的摘要已同步（`state_sync.py` 会查这个）
- [ ] 账本已补上本章行
- [ ] `preflight.py` 通过（严重 0）
- [ ] 讨论中产生的**结论**已落盘（不是只留在会话里）
- [ ] 有半成品想法 → 写进 `notes/` 或 `outline/待拍板清单.md`

## 新窗口怎么恢复

本插件已经把这条路铺好了，**不需要靠会话历史**：

```bash
cd <书目录>
python tools/brief.py            # 写前接地单：上一章末状态 + 本章节拍 + 待接伏笔 + 正典摘录
```

加上会话恢复协议（`AGENTS.md §1`）：`SOLOENT.md` → `canon.md` → `now.md` → `ledger.tsv` → 最近 1–3 章。
**这套顺序是刻意设计的：全部读文件，不依赖任何会话内记忆。**

若挂了 SessionStart 钩子，`SOLOENT.md §7+§8` 与 `canon.md` 会在会话开始时**自动注入**，
连"记得去读"这一步都省了。

## `/compact`：不换窗口也能降占用

当会话内容堆积过多时，用 `/compact` 把当前内容**总结为简短概要**，作为新会话的初始输入——
既保留核心信息，又降低 token 消耗。

**什么时候用**：
- 上下文到 100K 左右，但当前任务还没做完（不想打断）
- 讨论很多、结论还没落盘——先 `/compact`，再让 agent 把结论写进文件

**⚠️ 但 `/compact` 不能替代落盘。** 它是会话层的压缩，`SOLOENT.md` / `now.md` 是**文件层的事实**。
压缩可能丢细节，文件不会。**先落盘，再压缩。**

## 换模型时

单窗口进行到一定程度后换模型，新模型要读完旧模型积累的全部上下文，非常不经济。

**切换前务必先对前续会话做一次总结**，并把结论落盘。

---

## 一句话总结

> **文件是事实，会话是缓存。**
> 缓存可以清、可以压缩、可以换——只要事实在文件里，随时能重建。

这正是本插件把 `SOLOENT.md`、`canon.md`、`now.md`、`ledger.tsv` 全部做成**纯文本文件**的原因：
它们不属于任何一次会话，也不属于任何一个模型。
