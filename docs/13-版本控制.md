# 13 · 版本控制（Git）

> **这是本插件此前完全没提、但对长篇写作极其重要的一层。**
> 有了它，「整章重写禁止」这条纪律才有安全网——不满意就整体回退，而不是硬着头皮往下写。

## 为什么写小说需要版本控制

长篇创作里有三种不可逆的损失：

1. **AI 改坏了**：让它润色/修订，结果把打磨过的东西改没了；
2. **设定大调整**：改了一条世界观，牵连几十章的措辞；
3. **试错**：想试一条剧情线，走不通要退回来。

**没有版本控制时，这三种都只能靠"再改回去"**——而"再改回去"往往改不回原样。
有了 Git，任何时候都能回到那个"改坏之前"的干净版本。

> 官方原话：**「提交越频繁、粒度越清晰，回退时就越容易找到那个'改坏之前'的干净版本。」**

## 初始化

**`init_book.py` 不会替你执行 `git init`**——它只负责把 `.gitignore` 的托管段准备好。
Git 仓库本身需要手工初始化一次（SoloEnt 里：左侧边栏第三个标签 **源代码管理** →
点「初始化仓库」；命令行等价做法如下，均无需联网、无需远程托管）：

```bash
cd <书目录>
git init
git add -A && git commit -m "初始化项目骨架"
```

**`.gitignore` 由 `sync.py` 托管维护**：初始化/同步时自动写入两个 `managed` 标记之间的内容。
你自己的忽略规则写在托管段**之外**，sync 只替换段内内容，绝不整文件覆盖：

```gitignore
# >>> novel-writing (managed) >>>
# 密钥与本地环境（拆书脚本读取 API Key 的位置）
.env
.env.*
!.env.example
.soloent/.api.env
# 运行时产物
.soloent/watcher.pid
.soloent/watch_state.json
notes/watcher.*.log
notes/对账日志.md
__pycache__/
*.pyc
# <<< novel-writing (managed) <<<
```

> ⚠️ **密钥文件绝不能进 Git**：`.env`、`.soloent/.api.env` 是拆书/摘要脚本读 API Key 的地方。
> 一旦被提交，即使事后删除文件，密钥仍留在历史里——**只能轮换密钥**。
> `doctor.py` 会检查它们是否已被 Git 跟踪，报 ❌ 时用 `git rm --cached <文件>` 移出并提交。
> `.env.example`（只含空值）可以提交，作为需要哪些变量的说明。
>
> ⚠️ **不要忽略** `.soloent/book.json`、`canon.md`、`ledger.tsv`、`now.md`、`SOLOENT.md`——
> 那些是事实，必须进版本库。

## 什么时候提交

官方建议在每个**阶段性任务**完成后提交：

- ✅ 完成整本书的大纲
- ✅ 完成前 10 章
- ✅ 完成一次大的设定调整
- ✅ **每章过闸之后**（推荐，粒度最清晰）

本插件额外建议两个时机：

- ✅ **跑完 `/review` 之后**（评审通过 = 这一版是"好的"）
- ✅ **任何骨架层变更之前**（改卷纲/人设/数值体系前先提交，改坏了能退）

### 提交信息怎么写

SoloEnt 有「提交内容总结」功能可自动生成 Commit Message。命令行下手写，建议这个格式：

```
ch-31 许昂执念：集训返校 + 走廊对峙
正典统一：父名/殉职时间/振幅口径（19 处）
卷纲调整：第二卷增加峰会联赛线
```

**写清"这一版比上一版多了什么"**——回退时靠的就是这个。

## 与写作纪律的配合

| 纪律 | Git 怎么配合 |
|---|---|
| **整章重写禁止** | 重设计前先 commit；做完外科手术后对比 diff，确认没丢已验证文本资产 |
| **拍板留档** | 骨架层变动前 commit，变动后 commit 一次并写清理由 |
| **废稿归档不删除** | 直接靠 commit 历史保留，不必往 `notes/archive-*/` 里搬 |

### 回退怎么做

```bash
git log --oneline                # 看历史，找到"改坏之前"那一版
git diff <版本> -- chapters/     # 确认差了什么
git checkout <版本> -- chapters/ch-31.md    # 只回退一个文件
git revert <版本>                # 整体回退（保留历史）
```

⚠️ **别用 `git reset --hard` 一把梭**——它会丢掉工作区里未提交的东西。
优先用 `git checkout <版本> -- <文件>`（单文件回退）或 `git revert`（可追溯的整体回退）。

## Checkpoints（会话节点）

SoloEnt 还支持在对话中保存状态节点（checkpoint），可回退到某个节点重新开始。
**Windows 用户需要先装 Git**（[git-scm.com](https://git-scm.com)），没装不影响正常写作，
只是没有节点恢复功能。

> 提示"Git must be installed to use checkpoints"就是这个意思。

## 与本插件工具的关系

```bash
# 提交前先过闸，确保提交的是一个"干净"的版本
python tools/preflight.py        # 退出码 0 才提交

git add -A && git commit -m "ch-31 完成，闸门通过"
```

**这样历史里每一个 commit 都是"过闸的版本"**——回退时不会退到一个有硬伤的中间态。
