# 12 · 命令与操作

> 本插件沿用 SoloEnt 的命令约定。**四个内置命令**：`/init`、`/compact`、`/review`、`/market`。

## 四个命令

| 命令 | 作用 | 何时用 |
|---|---|---|
| **`/init`** | 生成 / 补建 `SOLOENT.md`（中央控制面板） | 项目**任意阶段**；已有内容也能从现有文件生成 |
| **`/compact`** | 压缩当前会话上下文，省 token | 上下文到 100K 左右但任务没做完 |
| **`/review`** | 对章节跑**五层质量审查** | **每章完成后、进入下一章之前**（官方强烈建议） |
| **`/market`** | 分析作品并生成发行 / 营销策略 | 手稿完成或接近完成时 |

---

## `/init` —— 生成中央控制面板

> ⚠️ **`/init` 不是"开新书"。** 开新书见 `01-初始化.md`。
> `/init` 是**生成或补建 `SOLOENT.md`**，而且**项目任意阶段都能跑**。

从 v0.2.0 起 `SOLOENT.md` 不再自动生成，要手动 `/init`。
它可以根据**现有内容或通过提问**来整理类型、主题、角色、情节等信息。

### 两种情形

**情形 A：新书（刚跑完 `init_book.py`）**
骨架已经生成好了，`SOLOENT.md` 里除了书名/题材/平台/字数之外都是空的。
这时 `/init` 的价值是**在商讨过程中逐步填充**——每定一条设定就并进对应板块。
不必一次填满。

**情形 B：已有内容但缺 `SOLOENT.md`（或面板过时）**
书已经写了几十章，但 `SOLOENT.md` 不存在、或者 §7 早就没同步了。
这时让 agent：

1. 读 `chapters/`、`outline/`、`world/`、`characters/`、`.soloent/`
2. 按 8 板块归纳出 `SOLOENT.md`（**摘要 + 指针，不要粘正文**）
3. §7 从 `.soloent/memory/now.md` 取，§8 从 `roadmap.md` 取

> **判据**：`python tools/state_sync.py` 会检查 §7 是否滞后。
> 报「SOLOENT.md §7 滞后」就是该跑 `/init`（或手工同步）了。

### 短篇可以不用

官方明确：**篇幅较短的项目或非虚构项目可以不初始化。**
本插件的骨架生成器会照常产出 `SOLOENT.md`，不用它放着即可，不影响逐章流程。

## `/review` —— 章节质量审查（五层）

官方强烈建议：**每章完成后、进入下一章之前跑一次**。这样问题在更容易修的时候就被发现。

| 层 | 查什么 |
|---|---|
| **1. 基础审查** | 字数是否符合目标；是否遵循细纲 |
| **2. 一致性审查** | 故事连续性（对大纲/幕结构）、章节流向（对上一章）、角色完整性（是否符合人设档）、世界规则（有无违反已建立设定） |
| **3. 写作风格审查** | 风格指南合规（对 `SOLOENT.md §5` / `.soloent/rules/story-style.md`）、角色声音、基调一致性 |
| **4. 章节结尾审查** | 钩子质量、**结尾陷阱**（重复用词 / 过长内心独白 / 软弱结尾）、与下一章的过渡 |
| **5. AI 写作模式检测** | 原创性、重复短语、**破折号过度使用**、**"词、词、词"列表模式滥用** |

**产出**：`notes/review-chapter-{章号}-{日期}.md`

### 与本插件工具的分工

⚠️ **`/review` 不能替代 `preflight.py`，反之亦然。**

| | 管什么 | 性质 |
|---|---|---|
| `preflight.py` | 正典冲突、数值、章号、句长分布、标点 | **机检**，可推导，失败关闭 |
| `/review` | 追读性、钩子质量、角色声音、AI 味 | **评审**，需要判断 |

**先过闸门（硬伤清零），再跑 `/review`（质量评审）。** 顺序反了会在有硬伤的稿子上做质量评估。

工作流文件：`assets/workflows/chapter-review.md`

## `/market` —— 发行策略

手稿完成或接近完成时跑。四部分：

| 部分 | 产出 |
|---|---|
| **1. 类型与市场分析** | 主类型/子类型、每章与总字数、市场分类 |
| **2. 故事元素提取** | 一句话简介（logline）、主要卖点、可比拟书名（comp titles） |
| **3. 出版路线推荐** | 最适合路线（传统/混合/自出版/同人平台）+ 理由 + 目标平台 + 后续步骤 |
| **4. 成功基准** | 可比书与指标、预计时间线、预算估算 |

**产出**：`notes/marketing-plan-{日期}.md`

工作流文件：`assets/workflows/publishing-diagnosis.md`

## `/compact` —— 会话压缩

把当前会话总结为简短概要，作为新会话的初始输入。

⚠️ **不能替代落盘。** 压缩是会话层的，`SOLOENT.md` / `now.md` 是文件层的事实。
**先落盘，再压缩。** 详见 `11-会话与上下文.md`。

## Plan / Act 模式

| 模式 | 行为 | 何时用 |
|---|---|---|
| **Plan（策划）** | **只出方案，不动文件**。分析问题 → 拆解步骤 → 征求确认 | 开新书、卡文、大改结构 |
| **Act（执行）** | 直接干活：建文件、改文本、跑命令 | 日常写作（默认） |

**推荐节奏**：新项目从 Plan 开始 → 计划确认后切 Act 执行 → 卡住或要大改再切回 Plan。

> 如果发现 agent 只给意见、不生成文件，**先检查是不是还在 Plan 模式**。

## 省 token 的两个高频操作

| 操作 | 为什么省 |
|---|---|
| **把文件拖进对话框** | 直接引用文件，不用把内容复制粘贴一遍 |
| **选中正文再引用到对话框** | 只带需要的片段，比整章贴进去省得多 |

**比复制粘贴更省，也更准确。** 让 agent 用 `Read` 工具读文件同样省——
别把大段正文粘进对话。

## 三个设置项（影响写作纪律）

| 设置 | 建议 | 为什么 |
|---|---|---|
| **自动审批 → 编辑项目文件** | 视习惯 | 不开则每次写文件都要确认；开了则可能覆盖已有内容 |
| **后台编辑（Background Edit）** | **想改稿前自行把关 → 保持关闭** | 开着时 agent 会在不抢走编辑器焦点的情况下改文件，你可能没注意到 |
| **子代理（Subagent）** | 探索类任务开启 | 只读并行探索，省主 agent 上下文；**但不能做生产输出** |

> ⚠️ **自动审批与「每章一停」的关系**：本库历史事故（19 章 69 分钟连发、设定全线漂移）
> 的机制成因就是"全自动批准 + 无人逐章校验"。
> **开着自动审批没问题，前提是闸门在跑**——`preflight.py` 是程序化检查，与 AI 是否守流程无关。
> 但"每章一停"是人工判断，两者不能互相替代。

### 子代理用在哪

**适合**：拆样板书（要读大量原文）、收集资料、分别阅读不同章节后汇总。
**不适合**：重复性任务（多个子代理反复读同一上下文反而浪费）、生产输出型任务（子代理没有写工具）。

详见 `02-拆书与边界.md`。
